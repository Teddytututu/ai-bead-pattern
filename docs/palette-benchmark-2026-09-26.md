# 24 / 291 色性能对照

运行环境：Windows、Intel Core Ultra 9 185H、Node v25.5.0、pnpm 11.19.0。数据是本机测量，不代表手机、共享云实例或模型推理的耗时。

## 耗时矩阵

命令：`pnpm benchmark:palette --full`。构建后也可直接运行 `node scripts/benchmark-palette.mjs --full`。

渐变图 128×128、仓库猫照片最长边 256、透明复杂边缘图 128×128；每组色卡先预热。覆盖 2 套色卡 × 3 张输入 × 4 个网格（32/48/64/96）× 2 个精修模式（fast/quality）× 2 个候选数（1/3），共 96 种配置，每种运行 3 次，总计 288 次。每张最多 20 色、一次局部搜索，三候选使用 faithful/simple/high-contrast。

以下是加入单次配色规划距离复用后的最终数据。运行中断时已完成 95 组，最后一组在新进程预热后补测，记录在原始 JSON 的 `resumedConfigurations`。没有丢弃已完成的慢样本。

全部运行返回 `success`。下表是每个网格在上述输入、模式、候选数及重复次数中的最大耗时，并非单个典型请求的平均值：

| 网格 | 通用 24 色最大耗时 | MARD 291 最大耗时 |
| --- | ---: | ---: |
| 32×32 | 543 ms | 900 ms |
| 48×48 | 1,303 ms | 1,999 ms |
| 64×64 | 2,176 ms | 3,512 ms |
| 96×96 | 4,588 ms | 6,801 ms |

MARD 291 单次范围为 89–6,801 ms，通用 24 色为 42–4,588 ms。本批最大耗时低于既有单候选 10 秒 / 多候选 30 秒目标；没有截断色库或增加既有测试时限。是否需要进一步优化，应由部署环境的实际负载决定。

完整结果包含每次耗时、质量状态和材料数：[原始 JSON](palette-benchmark-2026-09-26.json)。其中 `maxRssGrowthMiB` 只记录运行前后 RSS 增量，且共享预热后的进程，**不能作为峰值内存，也不能用于声称 291 色更省内存**。

## 独立进程内存

命令：`node scripts/benchmark-palette-memory.mjs`。每套色卡与输入各启动一个全新进程，固定 96×96、quality、三候选，并记录一次预热及三次运行后的 `process.resourceUsage().maxRSS`。此值包含运行时、模块加载、输入解码和生成全过程的进程峰值，单位转换为 MiB；不包含另一个独立进程。

| 输入（96×96、quality、三候选） | 通用 24 色进程峰值 | MARD 291 进程峰值 |
| --- | ---: | ---: |
| 渐变 | 218 MiB | 270 MiB |
| 猫照片 | 229 MiB | 255 MiB |
| 透明复杂边缘 | 252 MiB | 271 MiB |

这 6 个独立进程的三候选负载均低于既有 512 MiB 目标。差异包含垃圾回收和运行时分配的影响，不能推断色卡扩大会降低内存需求。[内存原始 JSON](palette-memory-benchmark-2026-09-26.json)另行保存，原耗时矩阵的 RSS 增量与此项峰值指标保持分开。

## 适用边界

本报告验证完整色库可用性、确定性预算和本机成本，没有将算法 `success` 等同于人类视觉验收，也没有验证实体豆子的色差。MARD 数据仍是仓库原有的第三方屏幕参考值，实测 Lab 可作为后续新版本加入。真实微信设备和远程神经分析不在本次性能测量范围内。
