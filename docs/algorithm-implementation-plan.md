# 拼豆生成算法实现规划

## 实现原则

实现顺序围绕一条原则：先确定目标网格提供的信息容量，再把容量分配给关键结构，随后完成颜色与网格表达。

完整流程采用七个阶段：

```text
输入图片
  ↓
图像理解
  ↓
构图与尺寸规划
  ↓
结构简化与关键特征保护
  ↓
固有色、光影与全局配色
  ↓
网格生成与局部美化
  ↓
多候选生成与排序
  ↓
图纸、材料统计与质量指标
```

`PatternAlgorithm.generate(request)` 继续作为产品侧唯一主入口。内部使用阶段化中间表示，各阶段可以独立测试和替换。

## 阶段化数据

| 数据 | 主要内容 | 作用 |
|------|----------|------|
| `UnderstandingResult` | 主体掩码、语义区域、关键点、轮廓、重要性地图、置信度 | 描述画面内容与辨识信息 |
| `CanvasPlan` | 裁剪框、网格尺寸、主体比例、构图评分、特征格数预算 | 分配有限网格资源 |
| `FeatureConstraintMap` | 特征位置、优先级、最小面积、允许位移、对称关系 | 约束结构合并、配色和网格优化 |
| `StructurePlan` | 简化轮廓、区域标签、大色块拓扑、保留锚点 | 固定最终画面结构 |
| `ColorPlan` | 区域固有色、亮暗层级、理想颜色、材料色号组合 | 统一全图配色 |
| `PatternCandidate` | 网格单元、材料色号、风格参数、局部优化记录 | 表示一个完整候选方案 |
| `CandidateEvaluation` | 辨识度、结构、配色、工艺、运行成本评分 | 排序并推荐候选 |

## 里程碑 0：契约与评估基准

预计用时：2 至 3 天。

### 工作内容

1. 确认画布尺寸的两种模式：

```ts
type CanvasOptions =
  | { mode: 'auto'; candidates: readonly GridSize[] }
  | { mode: 'fixed'; size: GridSize }
```

2. 为 `ImageAnalysis` 规划以下数据：

- `subjectMask`
- `semanticRegions`
- `landmarks`
- `importanceMap`
- `confidence`

3. 为生成结果规划推荐项与备选项：

```ts
interface PatternGenerationResult {
  recommended: PatternCandidate
  alternatives: readonly PatternCandidate[]
  evaluation: CandidateEvaluation
}
```

4. 建立首批评估图片集，建议采用：

- 人物 20 张
- 宠物 20 张
- 插画 10 张
- 复杂背景与特殊光照 10 张

5. 保存两类简单基线：

- A0：直接缩放 + RGB 最近色
- A1：面积缩放 + Lab 最近色 + 基础连通域整理

### 阶段产物

- 算法接口修订提案
- 60 张评估图片与来源记录
- A0、A1 的 32、48、64 网格结果
- 指标计算脚本框架

### 验收条件

- 相同输入与参数生成相同结果
- 网格单元数量、色号引用和材料统计保持一致
- 每次改动都能与 A0、A1 并排比较

## 里程碑 1：图像理解

预计用时：第 1 至 2 周。

### 输入

- 标准 RGBA 图片
- 用户选择的图片类型提示

### 输出

- 主体区域
- 人物或宠物关键点
- 语义区域
- 外轮廓
- 重要性地图
- 每项结果的置信度

### 实现顺序

1. 先接入人物检测、人脸关键点和通用主体分割。
2. 宠物阶段先覆盖眼睛、鼻子、耳朵、头部轮廓和主要花纹区域。
3. 重要性地图由语义权重、关键点距离、轮廓强度和主体置信度组合得到。
4. 低置信度输入采用通用显著性、边缘和主体中心先验。

### 验收条件

- 关键点可以稳定映射到原图坐标
- 主体掩码覆盖主要人物或宠物区域
- 重要性地图在眼睛、嘴部、脸部轮廓和身份特征处保持高权重
- 每个结果带有置信度，后续阶段可以据此调整保护强度

## 里程碑 2：构图与尺寸规划

预计用时：第 2 周。

### 候选搜索

对 32×32、48×48、64×64 等候选尺寸分别计算：

```text
CanvasScore =
  辨识度预测
  + 构图完整度
  + 关键特征表达能力
  + 轮廓空间
  - 制作成本
```

### 特征格数预算

每个候选尺寸生成一份 `FeatureBudget`：

- 双眼中心距离
- 单眼分配面积
- 嘴部宽度和方向
- 脸型轮廓锚点数量
- 宠物耳朵与花纹的最小区域
- 身体和背景的剩余面积

### 阶段产物

- 各尺寸的构图计划
- 推荐尺寸和推荐理由
- 每个关键特征的格数预算

### 验收条件

- 自动模式可以返回尺寸排序
- 固定模式可以生成对应尺寸的结构预算
- 推荐结果同时考虑辨识度、美观和总豆数

## 里程碑 3：结构简化与关键特征保护

预计用时：第 3 至 4 周。

这一阶段承担主要的画面信息分配工作。

### 处理顺序

1. 将主体、关键点、轮廓和语义区域映射到目标网格坐标。
2. 根据 `FeatureBudget` 建立硬约束与软约束。
3. 对低重要性区域执行边缘感知平滑和区域合并。
4. 对主体区域执行语义感知的大色块划分。
5. 简化轮廓，同时保留脸型、发型、耳朵、眼睛方向等锚点。
6. 生成目标尺寸下的 `StructurePlan`。

### 硬约束

- 双眼相对位置和方向
- 嘴部中心与主要形状
- 脸部和头部外轮廓锚点
- 宠物耳朵、鼻子和代表性花纹
- 用户手动标记的重点区域

### 软约束

- 发梢和毛发末端
- 服装边缘和局部纹理
- 次要阴影和高光
- 背景装饰

### 初期算法组合

- 边缘感知平滑
- 超像素或区域生长
- 基于重要性、面积和对比度的区域合并
- 轮廓简化
- 受约束的网格栅格化

### 验收条件

- 眼睛、嘴部和身份特征在目标网格中获得明确单元
- 关键点相对位置误差控制在 1 个网格单元附近
- 低重要性小区域数量相较 A1 明显下降
- 主体轮廓保持连续，背景复杂度得到压缩
- 结构阶段输出仍采用抽象区域和理想标签，颜色阶段随后赋色

## 里程碑 4：固有色、光影与全局配色

预计用时：第 5 周。

### 区域颜色模型

每个语义区域建立：

```text
固有色
  ├─ 亮部
  ├─ 中间色
  └─ 阴影色
```

首版采用区域统计、边缘保持平滑和相对亮度分层。S0 使用 Guided Filter，S1 使用 L0 smoothing，S2 使用 RTV；每条路线生成二档或三档阴影。完整 Intrinsic Decomposition 与 White-box Cartoonization 安排为第二阶段教师候选。

### 全局材料色卡选择

先从所有区域的理想颜色生成候选集合，再联合选择真实材料色号。目标函数包含：

- 区域色差
- 明暗顺序
- 冷暖关系
- 相邻区域对比
- 总颜色数量
- 关键特征清晰度
- 材料色号覆盖情况

### 验收条件

- 每个区域的亮暗顺序符合原图语义
- 皮肤、头发、衣服和背景保持清楚的颜色关系
- 实际色号数量满足 `maxColors`
- 眼睛、嘴部和轮廓色具有足够对比
- 全图色板在候选之间可以稳定复现

## 里程碑 5：网格生成与局部美化

预计用时：第 6 周。

### 处理模块

- 连通域分析
- 孤立单元整理
- 极小区域合并
- 一格宽横竖条检测
- 轮廓毛刺修整
- 对称特征一致性调整
- 阴影边缘整理

所有局部调整同时读取 `FeatureConstraintMap`。关键特征权重越高，允许位移和颜色合并范围越小。

处理顺序固定为：关键单元锁定、连通域整理、长条检查、2×2 对角拓扑、轮廓毛刺、对称性、3×3 或 5×5 局部搜索。局部能量同时包含颜色代价、边界一致性、小连通域、长条、拓扑、对称、颜色数量和关键特征违反项。

Graph Cut 用于一元项与度量型两两平滑项对照，OR-Tools 用于小窗口整数优化对照。首版主实现采用 OpenCV、scikit-image 与确定性局部搜索。

### 优化记录

每次调整记录：

- 调整位置
- 原色号与新色号
- 触发规则
- 原图代价变化
- 结构保护权重

这些记录用于调参、解释结果和后续训练。

### 验收条件

- 关键区域的保护单元保持完整
- 普通区域的孤立豆和碎片区域相较 A1 明显减少
- 长条检测可以区分轮廓线与量化伪影
- 网格调整保持材料色卡合法性和颜色数量限制

## 里程碑 6：多候选生成与排序

预计用时：第 7 周。

### 首批风格

- 还原
- 可爱
- 简洁
- 高对比
- 柔和

每种风格对应一组明确参数：结构细节预算、阴影层数、颜色数量、轮廓权重、对比度和工艺复杂度。

### 首版排序器

首版采用规则加权：

```text
CandidateScore =
  主体辨识度
  + 关键特征完整度
  + 轮廓质量
  + 配色协调度
  + 色块整洁度
  - 制作复杂度
```

用户每次选择推荐项或备选项时，记录同一原图下的成对偏好数据。训练、验证和测试按原始图片划分。

排序器按三步升级：

1. 规则权重与硬条件过滤。
2. Bradley-Terry 或 XGBoost pairwise，输入自动指标与风格参数。
3. 冻结视觉编码器与小型排序头，输入网格图、原图和自动指标。

### 验收条件

- 同一图片可以生成 3 至 5 个差异清楚的候选
- 推荐理由可以映射到评分组成
- 用户选择数据具有输入、候选参数、最终选择和修改记录
- 人工盲评中，推荐项相较 A1 达到预设胜率目标

## 里程碑 7：集成、性能与发布准备

预计用时：第 8 周。

### 工作内容

- 固化算法版本和默认参数
- 建立阶段耗时与内存统计
- 对 32、48、64 网格执行性能测试
- 确认小程序端与服务端的计算分配
- 运行消融实验，比较各阶段带来的改进
- 完成异常输入、超大图片和低置信度输入测试

首版部署采用服务端主流程。小程序负责图片压缩、方向处理、上传进度、轻量哈希和结果展示；服务端负责主体理解、尺寸评分、结构、配色、网格优化和排序。端侧 ONNX INT8 只用于 P1 图片类型分类与质量预检实验。

首轮服务端耗时目标设为 P50 5 秒、P95 12 秒。缓存键包含标准化图片哈希、算法版本、色板版本、画布选项、风格选项和模型版本。

### 消融实验

至少比较：

1. A1 基线
2. A1 + 尺寸规划
3. A1 + 尺寸规划 + 结构保护
4. 加入全局配色
5. 加入网格美化
6. 加入候选排序

### 发布指标

- 结构指标：关键点格数误差、轮廓 IoU、轮廓边界分数、关键特征覆盖率
- 配色指标：区域色差、明暗顺序一致率、相邻区域对比、实际色号数量
- 工艺指标：孤立豆比例、小连通域比例、细条纹长度、总豆数
- 审美指标：成对盲评胜率、用户候选选择率、生成后修改次数
- 工程指标：耗时、峰值内存、错误率、各阶段置信度

## 八周排期

| 周次 | 重点 | 交付 |
|------|------|------|
| 第 1 周 | 接口讨论、评估集、A0/A1、人物理解 | 可重复基线和第一版指标 |
| 第 2 周 | 宠物理解、重要性地图、尺寸规划 | `UnderstandingResult` 与 `CanvasPlan` |
| 第 3 周 | 特征预算、约束图、主体区域简化 | 第一版 `StructurePlan` |
| 第 4 周 | 轮廓简化、身份特征保护、结构调参 | 结构保护对比报告 |
| 第 5 周 | 固有色、亮暗层级、全局色卡选择 | `ColorPlan` 与色板对比 |
| 第 6 周 | 网格生成、孤立豆、条纹与轮廓优化 | 工艺优化候选 |
| 第 7 周 | 多风格候选、规则排序、偏好记录 | 推荐项与备选项 |
| 第 8 周 | 集成、消融、性能与默认参数 | 可交付算法版本 |

├─ contracts/       阶段数据与公共类型
├─ pipeline/        主流程编排
├─ understanding/   图像理解适配器

## 讨论节点

### 节点 A：接口契约

确认自动尺寸与固定尺寸的产品行为，以及推荐项与备选项的数据结构。

### 节点 B：首批图片类型

建议人物与宠物作为主线，插画用于稳定性测试，风景安排在扩展阶段。

### 节点 C：结构简化方法

比较超像素、区域生长、边缘感知平滑和受约束栅格化，选择首版组合。

### 节点 D：色卡与配色目标

确认 Generic Palette 的颜色来源、色数和视觉校准方式。

### 节点 E：部署位置

确认小程序端轻量预处理、服务端主流程和 P1 端侧 ONNX 实验的接口分工。

## 第一轮建议范围

第一轮聚焦 A0/A1、人物与宠物理解、自动尺寸、结构计划、基础区域配色和确定性网格优化。规则候选排序同步建立，训练型偏好模型使用真实选择数据启动。

第一轮成功标准建议设为：在固定测试集和盲评中，结构保护版本相较 A1 获得更高偏好，同时保持材料统计准确、色号合法和运行时间稳定。
