# MARD 291：单色深描边与身体填色

本次按用户确认仅更改 MARD 291，24 色兼容旧规则。算法版本为 `0.10.0-mard-ink-fill`。

2026-09-28 后续[配色协调性修复](mard-color-coherence-2026-09-28.md)已替代下文“全部结构边界硬保护”和额外 ΔE00 超过 2 即恢复的后处理规则；本页保留当时实现与实验记录，单色描边及非黑填色约束继续生效。

## 描边规则

外轮廓、内轮廓共用一个实体色号，关闭轮廓开关时不强制添加描边。以主体蒙版覆盖范围内的原图色相选取加深色；背景不参与选色，多色主体仍只使用一种描边色。

根据用户追加反馈，候选从最初 4 色扩大为 **12 色**。使用感知明度 `CIELAB L* ≤ 32` 和 `HSV 饱和度 ≥ 50%`，不再用 HSV 明度上限排除深蓝紫。当前固定版本 291 色卡满足条件的子集如下；输出始终引用原色卡色号，不生成新 RGB。

|---|---|---|
| B22 | #0A4241 | 深青绿 |
| B23 | #343B1A | 暗橄榄绿 |
| C12 | #1E334E | 深海军蓝 |
| C18 | #213244 | 暗灰蓝 |
| D4 | #162C7E | 深蓝 |
| D10 | #301A49 | 深紫 |
| D15 | #2F1E8E | 深蓝紫 |

优先保留一个描边色名额，然后选择其他材料色，仍遵守总用色上限。显式传入浅色、灰色或纯黑描边会被拒绝；产品 API 返回 `422 INVALID_CONTOUR_COLOR`。单个描边色库存不足时不会用多色拼接凑数。暗色身体与描边的对比不足会如实记录，不改用亮色违反约束。

## 身体填色与形状

- 自动选色排除名义纯黑 H7（色卡 RGB 实际为 `#010101`），保留 H16 等有色暗部。完整材料库和既有手工修改能力仍保留所有 291 色。
- 默认复用已有面积重采样；其策略参考 [OpenCV INTER_AREA 文档](https://docs.opencv.org/4.13.0/da/d54/group__imgproc__transform.html)。不新增手写分割网络或纹理滤波器，自动蒙版继续来自现成模型。
- 停止对已经缩小的网格做第二次偏移插值，避免条纹移位、变宽、变淡。保留逐格颜色分配，保护已有结构边界不被通用碎片/条纹清理吞并。
- 对身体清理结果增加颜色证据约束：相对于清理前的逐格匹配，如果清理使该格与源颜色的 ΔE00 再增加超过 2，就恢复原匹配。五官、描边和保留格不被此步骤改写。这不是成品整体色差上限。
- 外部占格仍依据神经蒙版、原有拓扑与边界算法；本次没有更改原图主体的几何蒙版，也没有增加对称或镜像假设。

## 使用

最新构建已就绪，执行 `pnpm demo:net`，选择 MARD 291 后重新生成。“轮廓”状态显示实际单色描边色号。微信 API 的 MARD 291 生成任务自动应用同一规则，无需新增请求参数。
