## P0：调研结论与契约准备

### 网上拼豆实例

优先使用作者或品牌直接发布的图纸作为设计参考：

- [Perler：All My Family](https://perler.com/blogs/projects/all-my-family) 提供家庭人物的项目与图纸入口，适合研究小脸的眼、嘴及发际线表达。
- [Perler：Woodland Friends](https://perler.com/blogs/projects/woodland-friends) 提供浣熊、猫头鹰、狐狸实例，可研究眼区、鼻口区与脸部色块的关系。它包含立体叠层和不同底板，取样时只选能对应方格的部分。
- [Perler：动物项目目录](https://perler.com/blogs/projects/tagged/animals) 用于扩展猫、狗和其他动物样本，记录每个实际采用的项目链接。

本轮已核验上述项目页；部分旧 PDF 地址失效，新图纸阅读器未成功解析。**尚未完成这些实例的逐格测量，不将某个项目宣称为已核实的 2×3 或 3×3 模板来源。**

P0/P3 的具体调研交付：

1. 整理至少 30 个可辨认五官的方格图纸实例，覆盖人物、猫狗、简化插画；避免同一图纸换色重复计数。
2. 对眼、鼻、嘴分别记录：包围盒宽高、实际占格数、锚点、眼间距/脸宽比例、嘴鼻间距、轮廓厚度、高光位置、背景对比、适用脸部格数。
3. 建立来源表，记录作者、链接、访问日期、可用范围及是否允许进入训练集；公开可查看的图纸首先用于观察，训练样本采用授权素材或自行设计的抽象部件。
4. 输出模板图鉴、逐格矩阵和失败反例；判断优劣依据图纸辨识度，而非模板数量。

### 定位与细线算法依据

- 人物定位继续采用已有 MediaPipe 路线。其官方输出包含面部关键点、表情信息和面部变换矩阵，适合作为姿态与部件范围的上游证据。[Face Landmarker 官方文档](https://developers.google.com/edge/mediapipe/solutions/vision/face_landmarker)
- 宠物继续复用现有 MMPose/AP-10K 路线。AP-10K 定义包含眼睛与鼻子，但不提供嘴部专用关键点；嘴部应采用单独的局部证据或人工锚点，不能把人脸模型的结果直接当作宠物嘴部真值。[MMPose AP-10K 数据定义](https://github.com/open-mmlab/mmpose/blob/main/configs/_base_/datasets/ap10k.py)
- 细线候选比较边界路径栅格化与局部细化，参考 Zhang–Suen / Guo–Hall。OpenCV 提供这两种二值细化方法；是否适用于本项目的一格轮廓，要在目标网格和拓扑约束下比较。[OpenCV thinning 文档](https://docs.opencv.org/4.13.0/df/d2d/group__ximgproc.html)

工程选择：复用现有轮廓和网格代码，离线用参考实现比较；平台无关核心不因本功能直接引入整个 OpenCV 运行时。

### Perler 123 色口径

Perler 官方商品页提供真实商品色号及官方色卡入口，例如 Midnight 的商品号是 `80-15201`；该入口指向 `Perler_Bead-Color-Reference_2025` 阅读器。本轮未从阅读器取得完整可解析清单。[官方商品与色卡入口](https://perler.com/products/1-000-perler-beads-midnight)、[官方链接的色卡阅读器](https://online.fliphtml5.com/rbjdq/svbs/)

现有开源 BeadColors 的说明列出 Perler 103 色，可作为有许可的历史 RGB 参考，但不能直接改名为 123 色。[BeadColors 数据仓库](https://github.com/maxcleme/beadcolors)

**2026-09-28 更新：123 个 SKU 已通过官方袋装商品目录冻结**，其中 118 个普通颜色参与自动匹配，5 个特殊材质保留完整登记。95 项 RGB 复用固定版本 BeadColors，28 项使用官方色样照片的屏幕估计值；逐项来源、历史 8 项差异及接入范围见 [Perler 123 接入记录](../../perler-123.md)。不声称品牌在任何日期都只有 123 色，不根据目录缺失推断停产，也不混入 Mini/Caps 系列。

## P1：明暗与色差专项修正

2026-09-28 新反馈为“选的色差很大”，具体失败原图、生成结果和参数尚未收到。已完成三套色卡接入回归及固定猫图 12 组阶段色差对照，见[排查记录](../../color-fidelity-triage-2026-09-28.md)；这些检查不能替代该反馈的原始案例复现，也不能宣布色差问题已修复。当前先补齐可回放输入并定位量化/后处理/参考 RGB 的影响，再冻结模板学习基线。

下表保留立项时的实现与问题，用于追溯修正原因；不代表当前源码。现行流程见[架构文档](../../architecture.md)，已落地修改见[明暗修正记录](../../value-fidelity-2026-09-26.md)与[轮廓和五官记录](../../contours-features-2026-09-27.md)。旧 `designRegionValues` 已无调用，并于 2026-09-28 清理。

| 部分 | 立项时实现 | 当时识别的差距 |
|---|---|---|
| 明暗链路 | `applyStyle → designRegionValues → buildValuePlan` 连续处理；后两步可同时生效 | 拆分风格化、明暗归纳与局部结构增强，检查重复处理及累计偏色 |
| 色彩保持 | `buildValuePlan` 将同组格子的 a/b 分量替换为组平均值，并强制拉开亮度层级/语义间隔 | 保留局部颜色变化，限制相对原图的亮度与色度偏移，避免全区域无界改色 |
| 色彩评分 | 已计算 `sourceFidelity`，但候选总分的 `colorFidelity` 取 `planFidelity` | 原图保真单独参与约束和排序，不能只证明结果接近已经改色的中间图 |
| 结构区域简化 | `mergeSmallRegions` 按尺寸和邻接颜色代价合并未保护小区域；`simplifyBoundaries` 可将格子归入占邻域多数的同源语义区域 | 小斑点、窄条纹和特殊颜色需要在合并前检测与保护；单凭区域小不能判为噪声 |
| 花纹模板 | 已有 `identity-mark` 类型及 1/2/4 格模板，但颜色角色只有 `identity-dark` | 扩展亮色、彩色及多颜色纹理角色，支持按证据自动选模板和直接保留不规则花纹 |
| 轮廓 | `outline-planner.ts` 已区分剪影和内部边界，具有对比度、节奏及拓扑整理 | 尚需提供明确的一格宽硬描边合同；生成默认值与产品 API 暴露范围要统一 |
| 默认配置 | `pipeline.ts` 中未指定 `outlineMode` 时，默认随 `valueLevels` 变化；不是所有结构生成都开启 | 结构预设显式开启外、内轮廓，并记录实际生效配置 |
| 五官模板 | 已有 1×1、2×1、1×2、2×2 眼睛及最高 3×2 的张嘴等模板 | 扩充 2×3、3×3 及更大模板；按眼型、表情、姿态和可用格数选择 |
| 五官位置 | 原单特征/双眼搜索扩展为有界联合落格 | 2026-09-27 已取消等高、同型与等面积偏好；按原图相对向量保留倾斜，允许不同尺寸或单眼，真实模型误差继续评估 |
| 人脸输入 | `ai-gateway` 已有 MediaPipe 映射；核心仅在收到 landmarks 时进入五官规划 | 排查实际 Demo/API 路线是否取得真实关键点；目录登记或适配器存在不代表推理已接通 |
| 嘴部输入 | 映射同时输出嘴中心及两嘴角，均为 `mouth` | 核查是否重复当作多个嘴模板放置；改为一个嘴组件、多个定位锚点 |
| 导出与显示 | PNG 所用 SVG 已绘制色号；已有 `bead-pattern-document-v1`，空格为 `-1` | 预览增加色号开关；统一导出选项和长色号排版 |
| 修改能力 | `adaptation.ts` 面向已制作格锁定及剩余区域重排 | 需要通用编辑会话，支持空格新增、擦除、任意色号和画布调整 |
| API | 已有生成、结果、导出与版本化色卡接口 | 尚无可编辑作品资源；生成结构参数目前仅公开 `occupancyMode` |
| 训练 | 已有偏好记录、线性排序模型、训练/验证/留出划分 | 补模板选择训练和真实人工标签；冻结三套色卡的数据版本与评估条件 |

以上是代码行为与待验证问题，不直接断言它们就是每个失败样例的根因。P0 需逐级导出：原图 → 实际分析证据 → 目标格蒙版与采样 → 五官位置/结构映射 → 风格调整 → RGB 明暗归纳 → Lab 明暗/轮廓规划 → 材料色映射 → 精修后图纸，定位信息在哪一步丢失或颜色在哪一步漂移。

### 本轮明暗检查：已确认的行为

以下为实施前的只读审计记录（旧算法 `0.7.0-preference-learning`）。后续实现已修改算法并添加回归测试；保留旧行为用于解释修正原因，不能把本节当作新版本现状。

| 检查点 | 代码证据 | 影响与需要验证的范围 |
|---|---|---|
| 两次明暗归纳 | `designRegionValues` 先按 RGB 亮度分档并对三个通道加同一偏移；有详细颜色证据时再调用 `buildValuePlan` | 偏移、取整和通道截断后又重分 Lab 亮度，可能累计失真；`faithful` 风格本身不改色，但仍会经过后续明暗流程 |
| 区域色彩被平均 | `plannedLabs[cell] = [role.targetLightness, meanA, meanB]` | 不仅改变亮度，还会改变局部色度和色相；同一语义区中的不同毛色、腮红、肤色变化可能被抹平 |
| 固定亮度间隔 | 两级角色最小间距 8，其他情况 6；眼/肤、脸/发、主体/背景默认间距分别为 16/10/12 | 低反差区域可能被强行拉开；语义整体平移只受 Lab 亮度 0–100 边界限制，没有相对原图的偏移上限 |
| 语义约束跨组应用 | `enforceSemanticGaps` 对眼与皮肤等类别执行组合遍历，未在这里限定同一实例或实际邻接 | 需要检查不同人物/区域之间是否互相牵动，以及误识别、浅色眼区和深色皮肤/毛发的影响 |
| 轮廓与明暗角色耦合 | 开启轮廓后，将 outline 角色一起放入 `separatedTargets` 排序拉距 | 开关轮廓可能同时移动非轮廓区域的亮度；P2 必须解除这种耦合 |
| 合成光照与材质调整 | 生效的 ValuePlan 路线上传入艺术方向的 lighting，并叠加材质角色偏移 | 需要区分原图真实明暗与算法额外添加的明暗，保真模式不应默认重打光 |
| 零强度不完全归零 | pipeline 将语义间距强度夹到 0.25–2，传入 `valueOrderStrength: 0` 仍有非零间距 | 增加真实的禁用/零强度语义，不能只把界面滑块置零却继续执行强制增强 |
| 配色与优化追随已改色目标 | PalettePlan、配色优化、网格精修使用 `plannedLabs`；候选颜色评分使用 `planFidelity` | 后续即使匹配准确，也可能只是更准确地匹配了偏色目标；原图指标虽存在，未在这个总分颜色项中直接使用 |

**已复现的合成结果**：均直接调用 `buildValuePlan`，`levels=3`、全格有效、没有传入光照或材质调整；除第三项比较外，轮廓关闭。这些结果发生在材料色卡量化之前。

| 样例 | 输入 Lab / 设置 | 实际结果 |
|---|---|---|
| 同一个 `face-skin` 区域含两个颜色 | `[50,50,30]` 与 `[50,-20,-30]`，2×1 网格 | 都变成 `[50,15,0]`；调用现有 ΔE00 实现得到约 **19.20 / 43.33** 的色差 |
| 浅色眼区与深色肤区 | `eye=[70,0,0]`、`face-skin=[35,15,10]`，各占一格 | 眼区变成 `[31,0,0]`，亮度下降 **39**，ΔE00 约 **38.97**；肤区不变 |
| 只切换轮廓 | 5×5 单一区域全部为 `[50,0,0]`，比较 `off` 与 `full` | 中心非轮廓格从 `[50,0,0]` 变为 `[56,0,0]`，亮度增加 **6** |

这些小样例确认算法具备造成明显偏色的机制，但不代表已经证明用户某张照片的最终偏色幅度。仍须用真实图、实际分析证据和最终材料色号做端到端归因。上面的 ΔE00 数值来自项目当前实现，其标准样本正确性也列入专项核验。
