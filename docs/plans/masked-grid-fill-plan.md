# 区域修复：先周边，再蒙版区，保留肤色底图

2026-09-30 用户最终确认：**“先在蒙版区填肤色”“先周边再蒙版区依旧保留”“就是保持原逻辑”**。当前实现以此为准。此前提出的中性灰挖空输入不再采用；基础模型继续使用 SDXL Inpainting，仅训练 LoRA 的范围不变。

## 固定流程

1. **先周边**：先用现有工作台生成完整拼豆图，选择可改区与锁定格，检查周边图案和配色。从有效蒙版外提取全图材料与两格邻域色调，建议底色色号；用户可指定当前材料集合中的肤色。冻结图纸、色卡、蒙版、底色选择及生成参数，返回上下文指纹。
2. **再蒙版区**：保留原来的肤色底图逻辑。完整拼豆图的周边保持不变，蒙版内预铺与周边协调的肤色，再把完整图与二值 mask 交给 SDXL。这里没有灰色或透明占位区域。SDXL 自身的 masked-image latent 分支仍按标准 inpainting 流程处理 mask。
3. **完整填充与协调**：从模型输出逐格填满有效区域，包括原来的空格；在材料集合内量化。以周边可见格估计的颜色漂移作有限修正，并对周边已有材料给予柔性优先。周边与锁定格直接复制，局部修复不能导致全图重新配色。
4. **检查再接受**：空格、透明残留、无变化候选不能交付。“结构修复”另拦截四格及以上区域的单色／低对比结果；“色调协调”允许合理纯色填充。失败按固定种子序列最多三次，仍失败则不提供可接受候选，保留原图与原因。
5. **接受与导出**：检查眼型、表情、配色和边界，填写原因后接受。材料数量随填充重算，可撤销。可改区仍有空格时禁止导出完成图；回放文件可保存失败草稿。

“不留空”覆盖指定的可编辑蒙版范围；图案外原有空板不自动铺满。蒙版内的空格若被锁定，需先解除锁定，不能静默跳过。自动建议的底色仅是邻域主要材料，不是肤色语义识别；用户需核对或指定。结构检查也不能替代人工判断五官是否正确。

任何请求输入变化后指纹失效，必须重走第 1 步。第二步必须携带与当前输入匹配的准备指纹。程序诊断按同样顺序运行，其准备事件不能冒充人工确认。

## 已实现与验证

- region-generation-v3 两步 API 和 Demo 已实现，旧 v2 记录保留，v2 请求不会静默切换语义。当前不再提供原图单条件替代拼豆上下文的入口。
- 模型输入预览与实际送入模型的肤色底图一致；支持自动建议／手动肤色色号，底色变化使周边确认失效。
- 回归通过：后端 20 项，Demo 81 项；覆盖手动／自动肤色、原空格填充、周边／锁定保护、过期请求和拒绝候选。
- 512 合成诊断一次得到候选：有效区 41 格全部有色，20 个原空格补齐，23 格变化，范围外／锁定变更均为 0；使用 6 色，底色为周边的 diag-2。
- 推理 12.600 秒，PyTorch 峰值分配 5263 MiB。证据：output/diagnostics/sdxl-skin-context-v3-512/。
- 真实浏览器流程通过：禁止跳过周边确认、参数变化失效、铺肤色生成、接受／撤销、材料统计、撤销后禁止导出留洞草稿、回放与主工作台带入。证据：output/diagnostics/sdxl-skin-context-browser-v3/。
- 结果具备局部眼样结构，但眼型、高光与另一只眼不一致；**填充检查通过不等于五官质量通过**。未启动正式 LoRA 训练。

中性灰尝试 output/diagnostics/sdxl-masked-context-v3-512/ 仅为被后续用户更正覆盖的历史诊断，不作为当前产品行为。

## 后续验收

三套色卡与真实图案仍需独立对照：对比原流程、相同底色的无 adapter／有 adapter、协调强度 0／开启、固定区域和候选预算，评估边缘、色差、可辨识度和人工接受率。正式 LoRA 数据采用“周边确定 → 蒙版铺肤色 → 完整目标格图”的任务描述，监督目标保留完整细节；分组与使用资格仍需审定。原图可保留供人工参考，未来附加语义参考也必须保留确定的拼豆周边条件。
