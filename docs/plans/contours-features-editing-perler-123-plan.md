## 本期目标与执行顺序

目标是让生成结果中的主要轮廓和五官可辨识、控制相对原图的不必要色差，并允许用户直接把结果修成可制作的图纸。配色缺陷已有首批修正，后续模板学习仍须在冻结的质量基线上验证，避免增强五官时扩大偏色。

结构算法另增加两项明确要求：**根据图像证据自动选择和使用模板；识别区域内有辨识价值的特殊颜色及纹理，在简化图像时保留它们**。例如猫狗的白斑/花毛/条纹、脸部局部颜色、服饰色带和小面积图案，不能统一变成区域平均色或大面积单色色块。这里的“特殊颜色”指图像中的局部颜色特征，与 Perler 色卡中的珠光、透明等特殊材质分开处理。

固定样图已覆盖三套色卡；尚需扩展人物、多色宠物、逆光等场景，补分区误差、消融、真实输入回放与验收。反馈者当时的具体原图和配置仍缺失，已修复的可重复代码缺陷与该反馈的完整复现分开记录。

### P1：对照实验与误差归因

1. **固定条件**：同一规范化原图、mask、裁剪、尺寸、sourceMapping、库存、色卡版本、随机种子和生成色数上限。分别覆盖无语义分析和有详细分析两条路线，记录 `colorPlanningActive`，不能把不同路线的差异全部归因于明暗算法。
2. **建立两个配色对照**：完整可用色库逐格最近色，作为不受单图用色数约束的参考；另做相同用色上限下、不加明暗增强的基线。前者不宣称为受色数/结构限制问题的可行最优解。
3. **保存每级颜色**：按当前实际路线记录原图采样、结构重映射、风格处理（若启用）、Lab 明暗、色卡量化和精修后的结果，注明生效与旁路阶段。几何映射固定时比较色差，另报几何变化，避免把错位当偏色。
4. **逐项消融**：比较保色／适度增强／风格化、零强度、结构取色位移、轮廓开关、量化与精修保护。旧 RGB 分档、a/b 平均和两次明暗叠加只在固定历史版本中复现；当前产品不重新启用这些旧机制。必要时增加两因素交互对照。
5. **分解报告**：每级相对同一原图参考的 ΔE00 均值/中位数/P95、`ΔL*`、色度变化、有效色相变化、通道截断/色域越界比例；低色度区域不使用不稳定的色相角评估。报告同预算基线与增强结果的指标差值，不能把各级 ΔE00 简单相加。
6. **分区统计**：全图、主体内部、脸部、五官、轮廓和背景分别报告；肤色/毛色区域保留有符号亮度偏移，避免正负变化在平均中互相抵消。固定 ROI 的结果与全图结果同时展示，不能只剔除受影响区域。
7. **样本覆盖**：纯色、低反差灰阶、渐变、高饱和色、接近黑白、透明边缘；真实人物的不同肤色、白毛/黑毛/多色宠物、逆光、低照度及有彩色光的照片。色彩预处理同时检查 sRGB 规范化、透明度合成、RGB/Lab 转换和色卡 Lab 来源，区分算法偏色与显示/数据问题。
8. **三套色卡对照**：通用 24、Perler 123、MARD 291 均已接入，使用相同样本矩阵分别报告材料色域不可避免的误差，以及相对于同预算直接配色额外引入的误差。

交付阶段对比图、色差热图、机器可读数值表和原因排序；每项结论写清触发条件，不能只凭肉眼认定“更鲜艳所以更好”。

### P1：持续保持的约束与剩余验收

下列约束的首批实现已有记录；后续门禁验证其跨场景表现，不把已实现参数重新列为待开发。

- **解耦描边与整体改色**：外/内轮廓可以独立工作，关闭明暗重塑不关闭轮廓和五官保护；outline 角色不再迫使整个区域的 base/light 角色整体移动。
- **统一明暗入口**：收敛 RGB 与 Lab 两次归纳，明确唯一的明暗调整阶段。保真模式默认保留原图局部颜色；只有用户选择增强/风格化时才进行受限重塑。
- **保留色度**：明暗调整优先只改受约束的 L*；区域平滑/颜色归纳单独控制，不能默认替换所有 a/b。处理高饱和色时检查目标色域，不能靠截断三个 RGB 通道掩盖问题。
- **有界局部增强**：按原图动态范围、局部置信度及同实例邻接确定对比需要；对亮度偏移和额外色差设预算。不能通过整张脸或整片毛发变色来满足眼睛/描边的局部对比。
- **不足时降级**：放松非必要明暗层级或减少角色数；若与用户指定硬轮廓/五官约束冲突，提供可解释候选和诊断，不能无限拉开颜色。不能在色阶不足时硬造多级阴影。
- **产品与 API**：沿用已实现的 `structure.valueMode: preserve | adaptive | stylized` 与 `valueStrength: 0..1`；`faithful` 默认 preserve，零强度真正旁路明暗重塑，其他风格显式记录其处理。Demo/API/SDK 继续保持同一契约。
- **修正排序与训练指标**：原图色彩保真与计划一致性分开命名、显示及参与评分；保真风格优先满足源图颜色预算。不能直接沿用当前总分作为 P9 的正向训练标签，让模型学会奖励偏色。

验收分两层：

1. 确定性回归：保真/零强度模式在未启用局部干预时保持输入 Lab；保留同一区域真实色度差异；上述三个样例不再出现无请求的色彩平均、无界亮度下降和轮廓引起的内部提亮。固定色表时开关轮廓只改变批准的描边/局部干预格；允许重新选色表时单独报告因色数预算竞争造成的间接变化。
2. 真实图片 gate：以同色卡、同尺寸、同色数预算基线比较，保真模式的额外 ΔE00 和亮度漂移不得超出预先冻结的容差，五官/轮廓辨识度同时达标。按三套色卡及关键区域报告，不只看全图均值；容差在 P1 基线报告中冻结，再进入 P2/P3 默认配置和 P9 训练，不能根据最终测试集临时放宽。

首批修正与确定性回归已完成，三套色卡均已有固定样图记录；剩余工作是多场景真实质量 gate、完整消融和分区热图，不能将已有 Perler 修复和对照重新标成未做。

## P2：由蒙版生成一格宽轮廓

### 产品行为

- 两个开关：`外轮廓`、`内轮廓`。结构算法预设均默认勾选；用户显式关闭时尊重设置。这里将“默认必选”解释为默认启用，并保留用户提出的可选能力。
- 外轮廓是主体剪影边界；内轮廓是头发与脸、下巴、肢体交界等主要语义边界。不会对同一条边界内外各画一圈形成双线。
- 线条落在实际拼豆格上，目标厚度为 **1 格**。屏幕上的亚像素细线只能用作辅助覆盖层，不能冒充可制作的拼豆轮廓。
- 自动选取能与邻域区分的材料色，也允许用户指定当前色卡中的线条色；轮廓实际占用的格子和色号必须进入材料统计。
- 仅有主体 mask 时可可靠提取剪影，不能由它凭空推出全部内部结构；缺内部证据时明确降级到筛选后的区域边界，并允许修正。

### 算法与约束

1. **证据分离**：保存主体占位、外轮廓、内部语义边界三种数据；人工确认的主体 mask 保持最高来源优先级。
2. **外轮廓提取**：在目标格尺度复用轮廓追踪、coverage/SDF 与形状栅格化；将 `M - erode(M)` 作为对照基线，再在狭窄边界带内选择连续的一格路径。描边默认占用主体边缘已有格，不无条件膨胀主体。
3. **内轮廓筛选**：按语义区域邻接、置信度、目标格长度及结构重要度选主线；亮度边缘只作为补充，过滤毛发、噪声与密集纹理。前后遮挡边界只保留一次，并决定它属于哪一侧区域。
4. **细化与连通**：仅对线条候选带细化，不能把整个主体 mask 骨架化。保护端点、交点、耳尖、手脚和必要孔洞；检查前景/背景互补连通规则，区分视觉斜线连续性和实体占位的连接强度。
5. **五官避让**：五官包围盒、关键占格与留白带先参与规划；内部线条不得穿过眼睛或堵住嘴。冲突时执行受限改道、简化低优先级内线或推荐增大画布，并记录原因。
6. **颜色约束**：在完整材料色卡内寻找轮廓色，并计入生成色数预算；颜色解析后检查与两侧区域的可见差异。深色主体不能只机械叠加黑线；遵守 P1 的颜色预算，不能为描边而整体提亮/压暗主体。
7. **贯穿后处理**：生成 `ContourPlan`，包含占格、颜色角色、来源和保护级别；量化、调色、孤立格清理和 Grid Refinement 均遵守约束，最后再验证一次，不能只在初始阶段画线。

若一格轮廓、五官和色数预算不能同时满足，返回明确的不可满足诊断及建议，不能偷偷增加色数或输出“已满足”结果。用户的手工编辑可以覆盖自动轮廓；再次生成时保留或替换编辑应为明确操作。

### 验收

- 横线、竖线、斜线、折角、贴边主体、孔洞、细肢体等合成用例通过；指定必保轮廓在后处理后保留率为 100%。
- 一格宽以路径法向及局部邻域检查；交点、拐角列为解释清楚的例外，避免把合法拐角误判为加粗。
- 真实样例报告主要边界的一格容差 F1、无意断裂数、孔洞/连通分量变化、对比度与五官侵占率；P0 冻结基线后再确定数值改善阈值。
- 外/内轮廓开关分别生效，结构预设默认值在 Demo、API、SDK 一致。

## P3：模板库与五官位置

### 模板设计

扩展现有 `feature-template-library.ts`，保留原有小尺寸模板。模板按 **宽×高** 标注，不能把包围盒面积等同于实际用豆数。

| 部件 | 规则库初始尺寸族 | 变化维度 |
|---|---|---|
| 眼睛 | 1×1、2×1、1×2、2×2、2×3、3×2、3×3 | 睁眼/闭眼、瞳孔、高光、朝向、倾斜、猫狗眼型 |
| 大眼睛 | 3×4、4×3、4×4、5×5 | 眼白/虹膜/瞳孔分层；仅在脸部空间足够时选用 |
| 鼻子 | 1×1、2×1、2×2、3×2、3×3 | 人物简化鼻、猫狗鼻、侧面鼻 |
| 嘴 | 2×1、3×1、2×2、2×3、3×2、3×3、5×3 | 闭嘴、微笑、张嘴、猫狗鼻口连接 |
| 辅助部件 | 眉毛、眼镜、胡须端点的可选模板 | 仅对有可靠证据且影响身份的部分启用 |

这些尺寸是规则库的设计候选，不是已经从上述网页逐格提取的结论，也不限定专项生成模型的输出尺寸集合。大模板是否采用由脸部实际格数和辨识效果决定，不能统一把所有眼睛放大成 3×3。FT4 路线从完整图案和预测分图学习宽高与内容，规则库保留为对照和回退。

模板元数据包括：稳定 ID/版本、角色矩阵、锚点、占位与保留底色格、间隔要求、允许镜像/朝向、适用主体/表情/脸宽、颜色角色、来源及许可。角色采用深色、亮部、虹膜、皮肤等语义值，运行时解析成各品牌色号。高光须保留光照方向，不能简单左右镜像。

### 定位算法

1. **确认输入链路**：记录关键点是否真实返回、provider/model 版本、坐标空间和置信度。模型不可用时保留规则生成，并提供用户点选眼、鼻、嘴锚点的本地入口。
2. **按对象分组**：使用 `instanceId + featureGroupId`；单个嘴的中心与嘴角只是同一组件的锚点。眼睛解剖左右与画面左右分别命名，避免镜像错位。
3. **人物范围与姿态**：本次主线从已接入的 Grounded-SAM-2 部件蒙版取得独立眼、鼻、嘴范围、中心和局部方向；用实际部件关系保持倾斜与可见性，不把局部方向称作完整三维头姿。仅在调用方实际提供 MediaPipe 证据时使用其眼角、眼睑、虹膜或唇缘；整体人脸置信度不能代替每个部件的可见性判断。
4. **坐标映射**：统一经过上传图 EXIF/规范化、裁剪、等比 contain、目标格映射；存在 `sourceMapping` 时核验与区域变形一致。保存完整变换信息，禁止重复缩放或直接拿预览 CSS 坐标落格。
5. **尺寸预算**：现有规则路线由投影后的脸宽、眼框、眼距和嘴框筛选模板尺寸；专项学习路线将这些信息作为证据及合法边界，自行预测宽高，不能由框尺寸规则代填答案。两条路线都先检查眼睛分离、鼻嘴间隔与占格约束，再进入放置。
6. **联合搜索**：在现有双眼候选搜索上扩展有界 beam search，联合比较两眼、鼻和嘴。评分包括关键点误差、相对姿态误差、尺寸匹配、局部图像支持、材料色对比与工艺代价；碰撞、越界、侵入错误实例和破坏必要间隔作为硬约束。
7. **姿态保持**：用户已明确指出等高偏好错误。双眼比较实际相对向量与原图关键点映射的预期相对向量，不能把 `abs(yR-yL)` 最小当成目标；模板相同、面积相等也不能作为通用奖励。侧脸允许两眼大小不同或只出现一眼。闭眼和遮挡不强行生成圆睁双眼。该修正已接入搜索和最终评分，仍需真实照片验证。
8. **宠物与插画**：优先验证同一 Grounded-SAM-2 部件链路；MMPose/AP-10K 作为可选的宠物眼鼻证据，不能当作嘴部真值。图纸输入的读格、豆孔处理及独立眼部入口按五官专项验证，低置信时提供人工锚点／模板建议。第一轮不新增分割或关键点模型微调任务。
9. **人工修正**：允许拖动锚点、切换模板尺寸/样式、标记不可见、锁定已确认部件；仅重新求解受影响组件并检查邻域碰撞。逐格修改仍由 P6 提供。
10. **最终检查**：配色和精修后重新计算特征占格、对比度和可见性；选用模板及位置写入诊断与训练记录。

### 验收

沿用 [Feature Planning Gate](../feature-planning-gate.md) 的真实数据目标：眼睛 Top-2 接受率 ≥90%、嘴部 ≥85%、硬特征碰撞为 0、完整硬特征可见率 ≥95%。增加 Top-1 接受率，避免只展示备选质量。

至少覆盖 30 张独立人物图及 32/48/64 网格，并增加 96 网格、倾斜、侧脸、闭眼、眼镜、遮挡、猫狗和矩形画布分组报告。每组报告样本数与失败原因。现有协议 fixture 只验证评测工具，不能代替真实图片和人工标签。空间不足或本来不可见的部件单独报告，不能通过排除困难样例美化指标。

## P4：结构模板与纹理保留目标

结构算法默认采用“自动模板 + 特征颜色纹理保留”。平坦区域可保持平坦；有斑纹、局部异色或方向性纹理的区域按目标尺寸保留结构，不因它们属于同一个“脸”“毛发”“衣服”标签就合并成一种颜色。

已实现的特征格、轮廓与可信身份标记保护为本阶段基线，具体修复见 MARD／Perler 实现记录。P4 还需识别并保护新的纹理与颜色子区，不能把现有局部保护等同于完整纹理系统；区域归属、取色、量化与精修造成的损失须用分阶段对照确认。

| 图像特征 | 计划保留的内容 | 处理方式 |
|---|---|---|
| 白斑、眉斑、鼻梁异色、毛色分区 | 位置、颜色、大小及与五官的关系 | 特征色子区域 + 自适应斑块模板或源图形状投影 |
| 虎斑、尾环、服饰色带 | 主方向、宽度、间距和明暗/颜色顺序 | 条纹模板或沿检测路径生成的离散条带 |
| 雀斑、斑点、小面积彩色装饰 | 有依据的点位、局部密度、主色关系 | 点簇模板，允许稀疏化但不随机换位置 |
| 棋格、重复织物图案 | 可辨认的重复方向、周期、相位与占色比例 | 有证据支持的重复单元，限制在实际区域内 |
| 毛发细丝、细织纹 | 在当前格数下可表达的方向与疏密 | 少量方向性纹理；不能把所有高频噪声变成豆点 |
| 已经小于一格的普通细节 | 主要色彩和区域归属 | 正常面积采样；有身份意义且可容纳的特征可分配最小占格，否则明确提示尺寸不足 |

模板用于表达原图已有的结构；原图中不存在的斑点、条纹或对称花纹不能为了“更有纹理”而添加。复杂不规则花毛可以直接栅格化源图细节，无须硬套标准斑点模板。

### 区域特殊颜色与纹理检测算法

1. **在降采样和合并前取证**：基于规范化原图与主体/语义区域 mask，保存区域内颜色分布、局部边缘和多尺度细节。先检查上传缩小至 1024 边长是否已损失目标细节；诊断中记录源图到目标格的有效尺度。
2. **建立区域颜色子簇**：在 Lab 中进行带空间邻接约束的自适应分组，比较少量颜色原型/medoid 与单色均值基线；按局部颜色分布选择簇数，不为所有区域固定三档，也不跨对象平均颜色。
3. **识别有价值的局部颜色**：综合区域内颜色稀有程度、与邻域的色差、面积覆盖、边界持续性、重复结构和语义位置评分。保留相对暗底的亮斑、相对浅底的深斑和彩色斑；“稀有”或“高饱和”都不能单独作为保留依据。
4. **区分纹理、光照与噪声**：比较局部亮度变化和色度变化、多尺度稳定性、连通形状及方向一致性。细阴影或光照渐变不自动解释成新毛色；对 JPEG 噪声、压缩边缘、孤立坏点和不稳定高频降低置信度。RGB 图像中难以区分的情况保留源图证据并允许人工标注，不宣称能可靠恢复物理材质颜色。
5. **提取空间结构**：对稳定条纹估计局部主方向与间隔，对重复图案比较局部自相关/重复单元，对斑点提取连通块和中心分布；无需增加上游神经模型训练，先以可解释算法建立基线。没有明确周期时使用非周期斑块表示。
6. **目标格可行性分析**：计算细节投影后的覆盖、预计宽度/周期、需要的最少格数和颜色数；避免超过网格分辨率的重复图案造成混叠或摩尔纹。低分辨率选择更少但有代表性的条带/斑块，并保持原位置与方向；空间不足时推荐增大画布。
7. **形成独立证据**：拟增 `RegionDetailEvidence`，记录实例/区域 ID、源坐标 mask 或路径、颜色原型、方向/周期（若存在）、置信度、辨识重要度、来源和版本。它在明暗归纳前产生，不从已被平均的大色块反推“原始纹理”。

小面积但高置信、影响身份的颜色可以分配少量保留格；普通随机细节不会全部升级为硬约束。人工圈选“保留这一块颜色/花纹”可提升优先级，用户也可标注“这里是噪声”。

### 按算法选择和使用模板

复用 P3 的模板库、姿态映射和候选搜索，再加入区域细节模板。模板区分三类：五官部件、局部身份标记、方向/重复纹理单元；均包含稳定版本、允许尺寸/方向、颜色角色和占格约束。

自动使用流程：

1. 根据部件类型或 `RegionDetailEvidence` 召回模板族；保留直接投影源图、不使用模板的候选作为对照。
2. 根据目标格大小、局部形状与方向生成少量尺寸/离散朝向变体；重复纹理的起点、间距和相位锚定原图，不在区域中随意平铺。
3. 颜色角色扩展为亮色/深色/特征色/底色及多个颜色原型绑定；保持深浅关系与 P1 的色差预算，不能把所有身份标记都画黑。
4. 在完整色卡内解析角色，给高优先级特征色预留材料候选和总用色额度。额度与五官、轮廓共享，不能为每个小纹理都增加一种颜色或突破生成上限。
5. 评分比较源图局部匹配、颜色原型误差、位置/方向/覆盖比例、特征辨识价值与工艺代价；越界、占用其他对象、覆盖硬五官/轮廓和违反手工锁定格为硬冲突。
6. 使用有界候选搜索确定模板组合；第一版用确定性规则，P9 再训练模板排序和预算建议。若所有模板都比源图投影更差，选择源图投影；低置信时不强制套模板。
7. 输出所选模板、变换、颜色绑定、保护范围、得分及放弃原因；用户能查看、切换或关闭单个区域的模板，并恢复算法自动选择。

约束分配依次考虑用户锁定、硬五官与外形、重要身份色纹、一般内轮廓与装饰纹理；共同占格时先尝试移动/简化可调整项。已被用户设为硬约束的项不能静默降级，无法满足时返回尺寸或颜色预算不足的诊断。细节的外边缘也不能一律追加黑色内轮廓，避免彩色斑纹变成密集黑线。

### 主流程、编辑与接口接入

拟定结构主流程：

```text
规范化原图 + mask / 语义区域
  → 区域颜色与纹理证据（降采样、合并前）
  → 目标格投影 + 五官/轮廓/身份纹理预算
  → 模板候选与源图投影候选联合选择
  → 带细节保护的区域合并与边界简化
  → 保真明暗处理 + 特征色保留的材料配色
  → 能区分有效纹理与噪声的网格精修
  → 颜色、结构和纹理联合验收
```

- 拟增 `ProtectedDetailPlan`：保存目标格上的特征归属、区域边界、颜色原型绑定、最少可见格、允许方向/密度误差和保护级别。几何与颜色保护分别表示，最终色号解析前不把所有格子固定成预设 RGB。
- `mergeSmallRegions` 的小面积判定增加细节证据，`simplifyBoundaries` 不跨越受保护的颜色分区；大语义区域保留细节子区域 ID，后续 ValuePlan 不能再次按同一父区域把它们平均。
- 配色目标同时包含主体颜色与重要局部颜色的误差；精修中的孤立格、细条、棋盘等惩罚须检查纹理证据。源图确有的斑点、条带、棋格允许保留；一般区域继续清理无证据的噪声。
- 保护贯穿形状、明暗、配色和精修；每阶段报告丢失/合并/改色的细节数与原因。保留所有细节导致无法制作时生成简化候选，不静默抹除身份特征。
- 拟在生成结构配置中加入 `templatePolicy: auto | off | manual` 与 `textureMode: preserve | simplify | off`，结构预设默认 `auto + preserve`；关闭自动模板仍可直接投影并保留源图纹理。人工模板参数须校验模板版本、图片坐标、区域及色卡归属。
- Demo 和微信客户端提供区域细节覆盖层：检测到的颜色/纹理、保护强度、所选模板；可圈选保留/抑制区域并预览变化。API/SDK 使用相同配置，不允许客户端传任意执行代码或外部模板 URL。
- P6 的编辑文档记录细节证据引用、模板版本及人工覆盖；手工改色/擦除优先。P7 扩边裁切同步变换细节，缩放或重新生成重新判断格数/周期可行性，不能沿用已失效的纹理位置。

### P4 验收与训练衔接

验收集合至少覆盖白斑黑猫、三花/虎斑猫、带局部花纹的犬、不同肤色与局部脸部颜色、条纹/格纹服饰、纯色物体、阴影及噪声反例；同源图在 32/48/64/96 和矩形画布对照，并在 P8 后补齐三套色卡。

| 验收项 | 指标与检查 |
|---|---|
| 自动模板决策 | 实际按证据选择类型/尺寸/方向；记录选择与拒绝原因，允许选无模板；相同输入与版本结果可重复 |
| 特殊颜色保留 | 标注特征的可见召回率、对应区域 ΔE00、面积占比与中心偏移；分白斑、深斑、彩色斑报告 |
| 纹理结构 | 主方向、条纹数量/间距、斑点分布及密度误差；不用整图高频能量增加冒充纹理更真实 |
| 防止过度色块化 | 在人工标注的多颜色/纹理 ROI 内比较特征覆盖与纹理消失率；原本平坦区域不得凭空增加纹理 |
| 全流程保护 | 硬保护细节的颜色/占格约束保留率 100%；自动建议未保留时有明确原因，不把所有建议都宣称硬保证 |
| 与现有目标兼容 | 不破坏 P1 原图色差预算、P2 轮廓、P3 五官；不超出用色/格数上限，统计与导出一致 |

真实数据阈值先在 P0/P4 基线报告中冻结，并按可表达/尺寸不足分别报告，不能过滤掉失败样例。需要比较旧结构算法、仅保留颜色子区、仅模板、颜色+纹理保护、再加学习选择五种配置；固定原图、证据、网格和色数预算。

P9 增加“保留了身份花纹”“花纹被抹平”“颜色正确但位置错误”“无依据增加纹理”等人工标签；学习算法何时用模板、用哪个模板、保留多少细节，而不是奖励更多颜色或更密的纹理。模板排序共享已确认的训练范围，不新增分割/关键点模型微调任务。

## P5：色号一键显示

- 在图纸预览工具栏加入独立的 `显示色号` 开关，与网格开关分开；记住本地偏好，不触发重新生成、不改变图纸 revision。
- MARD 使用真实代码如 `A1`；Perler 使用经核验的品牌代码。品牌代码、商品 SKU 和软件短标签分开存储，不伪造所有品牌都使用 A1 格式。

- 长色号按长度调整字体/格子导出尺寸；若启用短标签，必须在图例给出完整映射。空白格不标色号。
- 统一预览及 PNG/SVG 导出的 `showColorCodes` 设置；导出允许显式覆盖，旧调用保持当前带色号的默认行为。JSON/CSV 始终保留真实色号数据。
- 验收覆盖浅色、深色、最长 Perler 代码、96×96、矩形图、缩放和移动端布局。

## P6：全色库逐格编辑与修改接口

### 编辑体验与数据

- 基础工具：单格画笔、连续拖动填色、橡皮、吸色、色号搜索、完整色卡选择、撤销/重做、保存/恢复。
- 可修改任意一格，也可向原来的空格放豆、把已有豆擦成空格；鼠标与触控坐标共用变换逻辑。
- “所有色号”定义为 **当前选择色卡的全部色号**：MARD 291、Perler 123、通用 24 各自完整可选，不限制在自动生成结果已用的颜色里。不同品牌转换属于显式换色卡操作，不能把同名代码默认为同一种豆。
- 自动生成的 `maxColors ≤ 48` 与手工用色上限分离；手工编辑可用满当前色卡。图纸和导出应能正确承载超过 255 的色索引，不使用 `Uint8Array` 存放完整材料索引。
- 复用 `PatternDocument v1` 的格子、色表、材料统计含义，增加 `EditablePatternDocument` 外层，记录作品 ID、revision、来源候选、色卡版本和编辑来源；编辑会话采用可重放命令与撤销历史。
- 命令以稳定 `colorId` 表达，服务端从冻结的色卡解析；JSON 网格继续用整数与 `-1` 空白。内存可用 `Int16Array`，覆盖现有最多 512 色的库容量。
- 所有统计来自当前网格重算或经校验的增量更新；保存、导出、候选预览不得读旧的原始结果。自动生成质量评分标为生成时参考，编辑后重新验算可制作性。
- 初始候选保持可追溯；手工改动优先于自动规划。重新生成先产生新版本/新候选，不直接覆盖编辑内容。

### 拟定核心接口

接口名为计划草案，P0 冻结类型后实现：

```ts
createPatternEditSession(document, fullPalette)
applyPatternEdit(session, operation)
undoPatternEdit(session)
redoPatternEdit(session)
resizePattern(session, resizeOperation)
exportEditedPattern(session, exportOptions)
```

基础操作为 `setCell`、`eraseCell`、批量笔画和 `resizeCanvas`。一次连续笔画合并为一个撤销单元；缩放预览不属于编辑操作。同一批次遇到非法坐标/色号时整体失败，不产生半张更新。

### 拟定 HTTP API 与微信 SDK

| 接口 | 作用 |
|---|---|
| `POST /v1/patterns` | 从属于当前用户的生成候选创建可编辑作品 |
| `GET /v1/patterns/{id}` | 获取内容、revision、色卡版本与保存状态 |
| `PATCH /v1/patterns/{id}` | 按 `baseRevision` 原子应用逐格/笔画/尺寸操作 |
| `GET /v1/patterns/{id}/exports` | 导出指定 revision 的 PNG/CSV/JSON，支持色号显示参数 |
| `GET /v1/capabilities` | 补充编辑尺寸、颜色数、批次大小及功能可用性 |

修改示例，色号只用于说明，`colorId` 由色卡接口取得：

```json
{
  "baseRevision": 3,
  "operations": [
    { "type": "setCell", "x": 12, "y": 9, "colorId": "从当前色卡取得的ID" },
    { "type": "eraseCell", "x": 13, "y": 9 }
  ]
}
```

API 坐标从 0 开始，界面行列可从 1 开始。保持既有鉴权、资源归属和请求大小限制；PATCH 复用 `Idempotency-Key`，相同重试不重复落笔，不同内容复用键应报错。过期 `baseRevision` 返回 409，客户端保留本地草稿供重新应用。撤销保存为新的 revision，不倒退服务器版本号。

SQLite 保存作品快照与必要操作历史；作品生命周期与生成任务的 24 小时临时结果分开，明确保留策略及 `expiresAt`，不能因原任务过期丢掉已经保存的编辑作品。导出缓存键包含作品 revision、色卡版本和渲染选项。

同步更新 `pattern-api-contracts`、OpenAPI、`wechat-client` 和小程序调用示例；现有 job/result/export 路径继续兼容。生成请求增加轮廓参数和经验证的五官人工覆盖参数；分析坐标固定为上传后规范化图像空间，并校验图片、实例及分析版本归属。

### 验收

以完整色库遍历填色/保存/恢复/导出验证每个色号；专项验证 MARD 索引跨越 255、图纸实际用色超过 48、空格新增与擦除、连续笔画撤销、断网重试、并发冲突和重启恢复。逐格总数、材料清单、CSV 与图纸颜色一致。

## P7：修改画布大小

尺寸指拼豆格数，与图片像素或屏幕缩放分开。提供自定义宽、高及常用预设，支持矩形。

| 操作 | 语义 | 对原有图纸的影响 |
|---|---|---|
| 扩边/裁切 | 选中心、九宫格锚点或偏移量，增减画布范围 | 原有格子保持颜色和相对位置，新区域为空白；缩小时预览被裁掉的内容 |
| 缩放图案 | 最近邻重采样到新网格 | 形状、线宽与五官可能改变，不生成混合色；显示变化并可撤销 |
| 按新尺寸重新生成 | 从来源图片重新运行轮廓、五官和配色 | 产生新版本；用户选择如何处理既有人工编辑，默认保留旧版本 |

首版编辑器允许宽高分别为 **1–96 格、总格数不超过 9,216**，沿用当前资源规模；生成端也增加当前核心合法范围内的矩形尺寸校验，具体可用范围由 capabilities 返回。超过现有限制的大画布须在性能评估后扩容，不由前端单独绕开服务端限制。

扩边/裁切同步平移或移除模板锚点、锁定格和轮廓注释；最近邻缩放后重新验证约束并标记旧的自动规划需要刷新，不能继续声称轮廓一定为一格宽。重新生成时重算全部坐标映射、蒙版和模板预算。所有尺寸操作均可撤销，并即时更新豆数、色数和材料清单。

## P9：模板、参数与排序训练

2026-09-29 新增[全图感知与自适应尺寸的五官模板生成专项](bead-facial-template-learning-plan.md)：逐格还原和预测分图保留完整图案上下文，审核产生部件尺寸与角色真值，再训练结合完整 ≤64×64 格图案与分图证据、自行决定模板宽高和内容的模型。直接提取、规则、检索和固定尺寸路线用于独立对照及回退，不能代替该专项的生成交付。当前仅写计划，未批量分图或训练。以下原有基线、数据切分和三套色卡要求继续有效。

当前仅有 35 个规则模板及既有偏好采集/聚合工具，不代表本阶段已有训练模型。先整理来源清单、真实失败样例和模板接受标签，完成下述基线与数据切分，再开始训练；三套色卡接入本身不是训练完成证据。

### 训练范围与样本

本阶段使用现有上游视觉模型。前三层是既定产品训练范围；第四层是新增五官专项的核心训练目标，其发布仍取决于数据与效果验收。不安排分割或关键点模型微调：

| 层 | 输入与监督 | 输出 |
|---|---|---|
| 模板选择 | 部件/纹理类型、区域格数、姿态/方向、关键点与细节可信度、局部颜色分布和人工接受/拒绝 | 是否使用模板、模板/源图投影候选、尺寸方向及放置顺序 |
| 参数策略 | 主体类型、目标尺寸、色卡、轮廓/五官/颜色纹理诊断与人工偏好 | 有界参数建议，如内线筛选、模板预算、特征色/细节预算、对比度及精修强度 |
| 候选排序 | 当前偏好特征，加轮廓/五官质量、特殊颜色纹理保留和色卡上下文；A/B/Tie 标签 | 最终候选排名与可解释贡献 |
| 模板生成（专项 FT4） | 完整 ≤64×64 格图案、预测分图、部件查询与合法约束；审定宽高及角色矩阵只作监督 | 自主预测的宽高、对应角色矩阵、锚点和置信度，或拒绝生成；具体训练、对照和停止条件在专项维护 |

模型只能在满足硬约束的范围内选择；不能学会通过关闭用户要求的轮廓、移动锁定格或超出颜色预算来提高分数。

P0 建立诊断集，P6 后通过自愿保存的修正结果补充训练标签；编辑行为不能自动等同于“更好”，需确认最终接受版本。收集来源图片、候选、模板 ID/版本、人工评价、修改差异、生成参数、完整色卡版本和算法版本。

首轮标注预算建议至少 180 个独立来源组，覆盖人物、猫狗、插画、轮廓复杂主体；以相同源图生成三套色卡、32/48/64/96 网格和主要轮廓设置的候选，再选取有区分度的对照标注。目标至少 1,000 条有效偏好/部件接受记录；这些是试验起点，不能代替统计置信度。模板参考图与用于照片转换训练的来源图分开登记。

上述预算服务原有选择／参数／排序任务。专项生成另按 FT1/FT2 清点 ≤64×64 格的合格完整图案与可变尺寸标签，不将下载图片数量当作合格部件数。96 格保留原流程及兼容性回归；不得将裁下的 64 格窗口宣称为全图。专项中“成品图纸模板重建”与“真实输入条件生成”分别报告，重建成绩不能替代真实转换收益。

### 训练与数据切分

1. 先通过 P1 的明暗与色差 gate，再冻结 P2/P3/P4 的确定性基线、细节证据及模板版本；保留旧算法候选、无明暗增强候选、无纹理保护候选作为对照。
2. 按来源图片及同一人物/宠物身份、同一原始图纸分组，固定 train/validation/test 切分，例如 60/20/20；同图不同尺寸、不同色卡、不同编辑版本必须在同一组，防止泄漏。
3. 模板选择路线先训练简单可解释的排序器，使用合法候选上的成对／接受标签。专项 FT4 无须以该排序器训练成功为前提，而是在 FT3 冻结对照后训练全图感知与尺寸／内容生成；主评测不提供正确宽高。生成输出经过角色、边界、占格与保护约束校验后再进入候选搜索，不直接写入最终图纸。
4. 在现有偏好学习基础上训练参数建议与候选排序。先使用共享模型加色卡分层，Perler/24/291 各自进行参数校准；数据充分后再比较独立模型是否值得采用。
5. 训练上下文补齐色卡版本、模板版本、目标格数与启用功能；稀疏分组回退确定性规则，明确报告未达到训练样本门槛。
6. 验证集用于调参；锁定测试集用于最终比较。人工评分以随机顺序、隐藏算法名称的图纸对照进行。
7. 做消融：旧算法、明暗修正、仅轮廓、仅模板、轮廓+模板、再加学习排序；分别展示三套色卡，防止把增加颜色或改变全局明暗导致的变化误归因于训练。

### 评估与发布条件

- 五官：Top-1/Top-2 接受率、位置误差、硬碰撞、最终可见率，按脸部格数和姿态分组。
- 轮廓：边界 F1、连通/孔洞变化、一格宽符合率、对比度、五官侵占。
- 特殊颜色与纹理：重要局部颜色的可见召回和色差、空间分布/方向/密度误差、纹理丢失与无依据新增率，人工判断身份花纹是否保留。
- 整体：人工胜率、偏好 log loss、原图/计划两套色差、亮度/色度漂移、同预算直接配色基线的额外误差、孤立格、总色数及制作复杂度；24/123/291 各自报告，不只汇报混合均值。
- 训练候选与原基线在同一测试集比较，报告置信区间及样本数。新模型必须在目标问题上有改善，且硬约束零回退；样本不足时保留实验状态。
- 输出数据 manifest、分组切分、随机种子、训练配置、模型文件、模型说明、按色卡评测和失败图集；冻结模型版本并支持回退。

“完成三套色卡训练”意味着三套都有真实样本覆盖、独立分组指标和可用策略，不要求机械复制三个权重文件，也不能把旧模型改名为 Perler 模型即宣告完成。

本地演示验收顺序：上传人物或有花纹的猫狗图 → 确认蒙版、锚点与特殊颜色区域 → 结构生成 → 分别切换外/内轮廓 → 查看自动选择的五官/花纹模板 → 对照纹理保留与简化结果 → 打开色号 → 用原图未使用的色号修改一格 → 擦除/新增 → 撤销重做 → 修改矩形画布 → 保存并重新打开 → 导出当前版本 → 对照材料统计。

随后通过 API/微信 SDK 重复创建、修改、冲突处理和导出，验证三套色卡均可完成流程。微信开发者工具完成本地验证后单独记录真机未验收部分，继续遵守既有本地优先安排。

实施时增加有意义的核心、契约及端到端回归，覆盖坐标变换、姿态、轮廓约束、所有色号、revision 冲突和尺寸变化；运行项目所需 test/typecheck/build。性能使用固定环境比较生成耗时、内存和 96×96 编辑/标签渲染响应，不把生成性能限制直接套到轻量编辑操作上。

最终交付：可运行功能、完整 Perler 123 数据来源、模板图鉴、训练与评测产物、更新后的 API/SDK、迁移说明、本地演示操作清单。保留 `pnpm demo`、`pnpm api:dev`、`pnpm wechat:build` 入口，并在实现完成后记录新增评测/训练指令；本计划不把尚未实现的命令写成当前可用。
