## 1. 已确认的任务边界

| 项目 | 本版含义 |

| 基础模型 | 采用已训练并可本地部署的开放权重生成模型；首轮验证 SDXL Inpainting，FLUX.2 klein-base-4B 为多图条件升级候选 |
| 训练范围 | 仅 LoRA 等 adapter；冻结生成主干、VAE、文本／图像编码器。首轮不训练额外尺寸头、排序模型、分割模型 |

| 区域 | 上游预测或人工指定的允许修改 mask，可包含适当邻域；每个有效编辑格必须填材料色，但不要求每格都变色或都属于五官笔画 |

| 几何与颜色 | 保留倾斜、左右不等大、闭眼和遮挡；允许简化，不补造没有依据的眼鼻嘴。材料色、锁定格和总色数受约束 |

## 2. 64 格与完整大图的决策

**当前执行完整拼豆图条件，先周边、再蒙版区，保留肤色底图。** 先由工作台生成完整格图并确认周边配色；完整格图按整数倍最近邻放大，在有效蒙版内铺上周边建议或手动指定的肤色，再把全图与 mask 交给 SDXL。最终仅读回有效区，范围外与锁定格直接复制。自动底色取邻域主要材料，不等于肤色语义识别，需要用户核对。

64×64 是最终格数，不是直接送入扩散模型的像素尺寸；当前工作分辨率支持 512/768/1024，矩形保持比例与格相位。放大不恢复已经丢失的语义，单格细节仍需在最终格图验收。

2026-10-01 用户更正：仅使用完整拼豆格图。蒙版在格图坐标中人工选择，训练与推理都不看原照片／插画；取消 I 与 I+G 后续计划。历史试验保留为记录，不作为当前依赖。

本机 8GB 已通过 512/1024 推理与 512 rank-4 LoRA 单步；正式训练配置与质量未定。尺度与更多模型的调研依据保留在[调研](local-region-generation-research.md)。

## 3. 输入、输出与合成协议

当前运行按 [region-generation-v3](../region-generation-v3.md)：先 prepare 确认周边与底色，再携带匹配的 contextSha256 生成。每个有效编辑格必须有材料色，允许补齐原空格；范围外与锁定格不变。任何输入变化均需重新确认。与 template-learning-v1、历史 v2 隔离。下表同时包含未来数据设计，额外字段不能直接传给严格的 v3 API：

| 字段 | 职责 |
| --- | --- |
| 输入条件 | 仅 currentGrid 与格级 mask；不接收 sourceImage、sourceMapping 或原图参考 |
| currentGrid | 完整 W×H 材料格、占用、色卡版本；输入取自人工修正前 |
| editMask / lockedMask | 同一格网中的可改区和硬锁定；上下文区域可更大，写入权限不随之扩大 |
| contextSha256 / skinColorId | 周边准备指纹与可选肤色色号；自动建议由可见邻域产生，生成底图与页面预览一致 |
| regionQuery | 主体／部件实例、图像侧别、可见性与生成指令；多脸不能混用区域 |
| workingView | 工作像素尺寸、整数渲染倍数、padding 与格网相位 |
| constraints | 允许材料、全图颜色上限、保留轮廓、邻域间隔与候选预算 |
| candidate | 工作图引用及映射后的格级候选；不要求网络输出角色名称、模板 ID 或自主宽高 |
| decision | 接受／拒绝／无需修改／证据不足及原因；未检出不能自动等同于原本未画 |
| provenance | 模型／adapter revision、种子、prompt、推理参数、耗时和显存；不虚构网络置信度 |

当前请求最多三次尝试，首个通过检查的结果提交人工审核；全部失败则不提供可接受候选。格级合成使用 editMask 与非 lockedMask 的交集填满材料色，其余格直接复制输入；全图 RGB 输出、VAE 漂移和蒙版羽化不能改变范围外格。量化使用当前材料集合，在全图色数预算内对周边颜色作有限协调，不能触发全图重配色。模型不可用、版本不匹配或候选不被接受时保留原图与失败记录；有效区留空时禁止导出完成图。

布局、padding、源图像素、工作像素和拼豆格分别命名。先在全图中限定区域，再让生成器决定区域内的结构；不增加单独的模板尺寸监督或放置搜索。必要的编辑区外扩应由独立、可回放的区域策略或用户操作确定，不能依赖目标答案。

## 4. 数据、标注与已有工作的迁移

### 已有产物保留

- 2,435 张原图已完成 SHA／解码复查；来源声明 79 张≤64 格、13 张超出、2,343 张未知。审定格数仍未完成，训练资格仍为 0。
- 240 张候选、24 例读格预览；24×3 次神经调用得到 35 个眼候选，覆盖 6/24 张，无鼻／嘴候选。未检出和失败保留，不补成真值。
- 1,862 条待审关联、2,034 个建议连通组；它们不是独立设计审定结果。
- 当前审核页支持占用、部件角色、分组、资格、浏览器暂存和 JSON 导出／离线导入；已有 25 项工具测试及浏览器流程检查。这些验证对应旧协议，不是区域生成效果。

### 迁移规则

| 原产物 | 新用途 | 不能据此宣称 |
| --- | --- | --- |
| 原图、读格、占用、坐标变换 | 构造完整格图、局部 mask 与回放 | 已有真实原照片／插画配对 |
| 部件框、角色矩阵与锚点 | 辅助区域定位／语义诊断；可选标签 | 每张都必须补齐这些字段才能训练 LoRA |
| 原预测与人工记录 | 保留来源和质量追踪 | 模型预测是人工真值 |
| 分组／使用资格工具 | 来源隔离与资格继承 | 相似组已审定或训练已获准 |
| v1 输入输出 schema | 旧实验可复现 | 已支持当前 v3 区域生成 |

已有运行目录不覆盖、不改哈希。新协议、数据转换和生成前后审核另建版本。旧[标注指南](../annotation-guide.md)只描述 v1 角色页；新 [SDXL 实验页](../../services/sdxl-region-sidecar/README.md)已提供完整格图对照、mask、接受／拒绝及回放导出。后者还没有服务端资格审定／训练集导入，不能自动将接受记录变为真值。

### 新训练数据

1. **图纸局部恢复集**：完整审定格图＋遮挡／扰动区域＋干净目标；用于格网和风格适配，可程序生成 mask，但需要检查数据质量。训练／测试按来源组先切分，再构造扰动，避免同图泄漏。
2. **真实格图修正集**：完整拼豆格图＋在格图上选择的可改区＋人工接受的修改后完整格图。无需原照片／插画配对；仍需核对格图、目标、独立分组与来源使用范围。

人工优先确认区域、表情／姿态、最终格图接受度、保留范围、分组及来源。逐格角色不是必填训练监督。生成模型或合成扰动可以提出候选，不能代替人工接受记录；无需为了 adapter 再从零标注一个通用分割模型。

## 5. 评测与通过条件

目标是最终可制作图纸，不用大图画质或模板宽高准确率替代验收。

| 维度 | 验证方式 |
| --- | --- |
| 局部可辨识度 | 眼型、闭眼／睁眼、嘴型、表情、倾斜和身份线索；最多三次尝试内的候选接受率，失败计入预算 |
| 全图一致性 | 格图中的另一只眼、脸型、姿态与邻域过渡；条件始终为完整拼豆格图 |
| 拼豆可用性 | 单格纯色、单格高光保留、用色与用豆预算、孤立格、接缝及无依据细节 |
| 硬约束 | 范围外修改格数为 0，锁定格变更为 0，越界／硬碰撞为 0；拒绝率另报 |
| 最终产品 | 24／123／291 色卡分别报告；32／48／64 网格、矩形、单格部件及小脸单列；96 格回归原流程 |
| 资源 | 本机峰值显存、主内存、冷启动、每候选耗时、训练单步和量化／卸载配置 |
| 来源与泛化 | 独立设计／身份分组，报告各组数量、置信区间和失败样本，不靠同角色近似图跨集合 |

对照包括：不修改／直接投影、现有规则、相同肤色底图的基础模型无／有 adapter、协调强度 0／开启，以及工作分辨率和局部裁剪消融。原图参考不再列为当前路线；换基础模型的结果不能混成输入尺度收益。

先冻结开发集和验收预算，再封存测试。相对最强可用基线，人工接受度应有可解释改善且颜色／轮廓不退化；具体容差与样本量在 FT3 根据基线冻结，不能将旧模板指标原样挪为新模型已通过。恢复成品图纸与改善真实输入分别报告。

## 6. 小样本验证与分阶段交付

### FT0：任务与实现冻结

- 采用本计划的 v3 肤色底图与两步协议，记录与 v1／历史 v2 的边界。
- 固定基础权重、训练仓库 commit、adapter 类型、依赖与本地资源上限；生成服务与现有 SAM2 环境隔离。
- 区分原生 inpainting、参考图编辑和最终格级合成；检查选用 pipeline 是否真的接收所需条件。
- 交付任务协议、模型清单、资源试验配置和标注迁移说明。2026-09-30 已交付 v3 流程；当前验证见填充计划，首轮记录保留。

### FT1：零训练生成和格网试验

- 使用自有／已确认可用的少量完整图，先测 VAE 编解码对格相位、白珠与单格高光的影响。
- 跑完整格图放大、周边确认、蒙版铺肤色的零训练局部生成；只使用完整拼豆格图，不加入原照片／插画条件。
- 验证格级合成、保护和色卡预算；保存所有失败、拒绝和资源不足。
- 在合格小样本上验证 LoRA 单步反向、保存／重载与基础权重未改变；这只算训练链路验证，不算正式训练完成。

### FT2：配对数据与审核入口

- 新增生成前后完整格图对照、编辑区、最终接受目标与原因；浏览器保存／后端导入边界明确。
- 先审定独立来源组，再切 train/validation/test；同一原设计、镜像、换色、近似版本及已知身份关联不跨集合。
- 构造局部恢复集；另采集真实转换修正集。记录缺少格图核对或人工接受目标的样本；缺少原照片不构成阻塞。
- 只导出质量、分组和使用范围符合要求的数据；旧数据不会因协议升级而自动获得资格。

### FT3：冻结比较

- 保持相同输入格图、格数、材料集合、编辑区和候选数，冻结原流程与零训练模型。
- 在同一模型内比较工作分辨率、全图条件、只给局部条件、量化策略；记录资源／效果取舍。
- 冻结盲评、接受率、范围外变化、颜色容差和成本预算；不需要先训练模板排序模型。

### FT4：只训练 Adapter

- LoRA 初始可比较 rank 8/16，batch=1、梯度累积／检查点等作为试验配置；不预承诺质量或 8GB 可运行的最高分辨率。
- 使用真正接收区域 mask 的训练路径；将采样适配成五官／邻域，按 v3 构造肤色底图与配对修正。监督目标保留完整细节；训练与推理均固定为完整拼豆格图条件，不含原图参考。
- 优化器只含 adapter 参数；记录参数名称／数量，基础主干、VAE、编码器权重前后核对。新增损失或采样逻辑不能悄悄扩大可训练参数范围。
- 先比较无 adapter 与有 adapter，再做输入条件消融。mask 内与边界的损失权重需实验校准；未知目标不作为确定监督。
- 导出 adapter、基础权重引用、数据切分、训练配置、曲线、评测和失败集。资源不足或收益不成立则保持实验状态。

### FT5：接入与回退

- 本地 sidecar 加载固定基础模型＋adapter；输入完整上下文与区域，输出候选及格级变更，不注册模板。
- 接入实验开关、区域重生成、接受／撤销、锁定和 API/SDK 的版本／坐标校验。
- 校验材料统计、导出与当前编辑版本一致；三套色卡分别验收。现有规则可回退，但必须标记实际来源。
- 演练范围外画布、无效格图、低证据、超时、OOM、模型／adapter 不匹配及用户手改后重试；不覆盖已确认格。

近期顺序：**FT0 新协议 → FT1 零训练与资源验证 → FT2 配对数据／审核 → FT3 → FT4 → FT5**。原有人工角色复核不再作为模型选型与零训练验证的先决条件；正式 adapter 训练仍需合格目标和独立分组。
