# 拼豆图纸五官提取与模板模型计划

更新：2026-09-29。状态：**方案评审稿，仅制定计划，尚未实施**。

目标：利用已下载的拼豆图纸和现有 Grounded-SAM-2，提取可靠的眼、鼻、嘴等部件，形成可训练的离散模板数据；学习选择和生成适合目标格数的模板，改善最终图纸的五官辨识度、表情和姿态保持。

本计划细化[当前实施计划](contours-features-editing-perler-123-plan.md)的 P0/P3/P9，并增加“受约束的模板生成模型”研究阶段。原有配色、轮廓、编辑和三套色卡质量要求继续有效；本计划不代表这些阶段已完成，也不启动批量推理、分图、标注或训练。

### 任务口径与默认选择

| 容易含糊的事项 | 首轮默认与验收含义 | 何时调整 |
| --- | --- | --- |
| “生成模板”是什么 | 输出目标格坐标中的颜色角色矩阵、锚点和约束；分割 PNG 只是中间证据 | 需要新角色或新部件时，先修改并版本化模板契约 |
| 模型做哪些五官 | 首版眼、鼻、嘴；眉毛／眼镜先作为上下文和遮挡标签 | 基线通过、样本足够且确有误差收益后，再扩独立类别 |
| 优先改善什么输入 | 动漫插画为主要效果域，动物和真人分开验证；不把图纸自重建当成照片转换评测 | 有相应域的真实输入、审定目标和独立测试后才扩主目标 |
| 左右、缺失与未知 | 左右按图像坐标；独立眼部允许未知侧；遮挡、原设计未画、未检出和未知分别记 | 有额外身份／姿态证据时补充标签，保留修订来源 |
| 首版在什么网格上工作 | 方格、能确认占用和格距的图纸；部件优先 1–8 格宽高 | 六角板和更大部件单独建协议，不直接拉伸成方格 |
| 模型是否在线生成 | 先离线生成、审核并冻结候选模板库，在线复用现有放置流程 | 真实输入的条件生成明确胜出后，再制定在线推理协议 |
| 没有可用模板怎么办 | 允许不使用模板、采用有效源图投影或提供人工锚点入口；缺乏证据时保留缺失诊断 | 只有新证据或用户明确修正才能补部件，不能靠对称猜测 |
| 怎样才算训练就绪 | 使用范围、格矩阵、部件标签、独立分组和验证集均明确 | 样本不足时补审定数据或缩小试验范围，不以增强版本凑独立样本 |
| 人工标注由谁确认 | 模型／助手预标注单独标识；进入金标准和偏好监督的结果由指定人工审核者确认 | 若暂时只有自动核对，保持候选状态，先做工具与流程验证 |
| “效果更好”的依据 | 在同预算最终图纸上检验五官表达、身份／表情、颜色和可制作性，附独立分组指标 | 局部指标上升但整体变差时，按失败预案处理，不能改成功定义 |

FT0 将这些默认写入任务协议。尚未观测到的硬件吞吐、可用真值数量和效果收益保持“待测”，不把建议值当成保证；若任务范围变化，保留决策记录并重估数据和评测需求。

## 1. 可行性判断与推荐路线

**方向可行，建议将 Grounded-SAM-2 用作候选五官的定位与分割工具，经逐格还原和审核后形成模板；先证明模板库与选择模型有效，再训练能产生新矩阵的小型生成模型。**

直接把 2,435 张整页图纸交给模型分图，再把裁剪 PNG 当成真值训练生成器，成功率和收益都不确定。关键缺口如下：

| 环节 | 可复用条件 | 尚需解决的问题 |
| --- | --- | --- |
| 五官识别与分图 | 已有文本检测、SAM2 蒙版和部件接口 | 拼豆图纸有圆环、豆孔、格线和图例，尚未在本批数据上测过识别质量 |
| 获得模板 | 图纸保留了手工设计的离散结构 | PNG 裁剪和二值蒙版都不等于逐格的颜色角色矩阵 |
| 学习模板分布 | 可以从审定的图纸部件学习形状、表达和尺寸先验 | 2,435 张图纸不等于 2,435 张独立脸，更不等于同等数量的训练真值 |
| 根据输入选模板 | 现有放置器、颜色角色和候选搜索可复用 | 图纸缺少配对原始照片／插画，需要补输入证据和接受／拒绝标签 |
| 改善产品效果 | 已有五官质量门禁框架 | 模板好看不代表放回当前脸部后正确；必须检查精修后的最终图纸 |

官方 Grounded-SAM-2 将开放词汇检测与 SAM2 分割组合；SAM2 本身是可提示的图像／视频分割模型，不能单独承担五官类别判定或模板生成。这支持其作为预标注工具，但不是在拼豆小五官上已达标的证据。[Grounded-SAM-2](https://github.com/IDEA-Research/Grounded-SAM-2)、[SAM2](https://github.com/facebookresearch/sam2)。

推荐先做 **图纸解码 → 现成模型预标注 → 校正 → 模板库 → 模板选择模型**，再按效果决定是否进入 **受约束的模板生成模型**。后者保留为明确交付目标，不能把前者的检索结果称作“已训练出新模板生成器”。

## 2. 已核实的项目与数据现状

### 2.1 已确认使用当前固定模型

用户在本轮已确认使用 **GroundingDINO Tiny + SAM 2.1 Small**。以当前仓库的 [contracts.py](../../services/sam2-sidecar/src/sam2_sidecar/contracts.py) 为固定基线：

- Provider：`grounded-sam2-local`。
- 检测器：`IDEA-Research/grounding-dino-tiny`。
- 分割器：`facebook/sam2.1-hiera-small`。
- [parts.py](../../services/sam2-sidecar/src/sam2_sidecar/parts.py) 已检测眼、鼻、嘴、头等类别；眉毛没有独立类别，虹膜和高光没有细分类。
- 部件分析依赖先检出主体，最多处理八个主体；孤立眼睛图纸可能在主体检测阶段就失败。
- 眼睛当前按蒙版连通域拆分。图纸中的离散珠粒、孔洞以及睫毛／高光不连通，可能使“一眼多块”被当成“多只眼”；这是待验证风险。

本轮只读访问 `127.0.0.1:7103/health/grounded` 被拒绝连接，未启动服务、加载权重或执行推理。模型选择已经确认，实施时记录 endpoint、两组件的固定权重 revision、预处理、设备和显存即可。首轮保持该组合，重点比较输入视图、局部识别和校正流程，不安排更换模型规模。

### 2.2 数据量与可用监督

以 [snapshot/summary.json](../../tools/bead-dataset/snapshot/summary.json) 和[采集说明](../../tools/bead-dataset/README.md)为准：

| 项目 | 当前实际数量／状态 |
| --- | --- |
| 有效图纸 | 2,435 张；动漫 1,606，动物 829 |
| 已确认动漫脸部／头像 | 115 张 |
| 已确认动漫眼部 | 23 张；含独立眼部设计，不能全部视为完整脸 |
| 已目视分类／待审核 | 739／1,696 张；这是题材核对，不是逐格或五官真值标注 |
| 五官蒙版、关键点、颜色角色真值 | 尚未建立 |
| 训练资格字段 | 当前全部 `authorizationStatus: pending`、`trainingEligible: false` |

本轮查看了现有联系表：图纸包含左侧配色表、右侧珠粒图、标题署名；尺寸差异大，也有六角底板、独立眼睛和多部件图。扩充样本多数 `gridSize` / `beadCount` 为 `null`，不能把 1124 × 720 图片尺寸当作格数。138 张脸／眼优先样本适合启动试验，但尚不足以证明可训练一个泛化生成器。

原图保留不动；派生裁剪、标签和将来的模板实例都继承来源、哈希及使用范围。训练集使用已确认可训练的样本，状态未确认的样本不自动转为合格；可另补自绘或已获许可的图纸与转换任务。这里记录的是当前元数据缺口，不对具体使用作法律结论。

### 2.3 现有模板接口与缺口

[FeatureTemplate](../../packages/pattern-core/src/planning/feature-template.ts) 使用 `width / height / anchor / cells[{x,y,role}]`；[模板库](../../packages/pattern-core/src/planning/feature-template-library.ts)有 35 个项目原创规则模板，具备眼暗部、高光、虹膜、眼白等角色。模板后续进入颜色解析、姿态放置和双眼联合搜索。

因此学习产物应输出**离散矩阵与锚点**，由现有色卡流程映射为材料色号。还需规划以下契约扩展，不能把它们当成现成能力：

- 区分“保留原底色”“明确留空”“未知／不监督”，避免删除该保留的皮肤；现有稀疏 `cells` 不足以完整表达训练标签。
- 来源类型目前只容纳 `original`，提取／学习模板须新增来源和训练版本信息，不能冒充原创。
- 学到的模板 ID 需要受校验的注册与版本管理；当前部分手动模板检查依赖静态库。
- 眉毛、眼镜等辅助部件需新增类别和角色支持，首版先做眼、鼻、嘴。

## 3. 方案比较

下表是基于现状的工程判断，效果均待试验，不是性能排名。

| 方案 | 适用性与代价 | 本计划选择 |
| --- | --- | --- |
| 整页自动分割后直接训练 PNG 生成器 | 实现表面简单，但易学到图例、豆孔、格线；输出仍需重新离散化，缺少输入到目标的配对监督 | 不作为首轮主线 |
| 逐格解码＋候选分割＋审核＋模板库＋小型排序器 | 数据要求较低，能直接接现有放置器，失败可定位；只能选择已有候选及允许的变换 | **优先建立可交付基线** |
| 在审定模板上训练条件式离散生成器 | 可产生新矩阵，符合专用模板模型目标；需要更多独立设计、尺寸覆盖及上下文监督 | **第二阶段试验**，必须优于上述基线 |
| 动漫关键点模型提供候选，再由 SAM2 修边 | 有机会改善动漫五官定位，但仍有拼豆域差异；只给关键点不等于语义蒙版 | 小样本对照，按收益接入 |
| 从头训练／微调五官分割模型 | 需要可靠分割标注，增加一条训练与维护链；可能把主要精力花在数据清洗上 | 初期不做，定位被证明是瓶颈后再立项 |
| 大型扩散模型／LoRA 直接画五官贴图 | 当前任务最终只需少量离散格和角色；缺少证据说明额外算力优于小模型 | 不作为首轮方案 |

可对照的现成模型：`hysts/anime-face-detector` 提供接近正面的动漫脸及 28 点定位，适用范围不能外推到侧脸、动物和低格数豆图；当前上游还要求 Python 3.12+，应独立环境验证，避免改坏现有服务。[作者项目](https://github.com/hysts/anime-face-detector)。真人 BiSeNet 面部解析可作后续真人域对照；其公开训练来源为 CelebAMask-HQ，不能据此假定适用于动漫豆图。[实现与数据说明](https://github.com/yakhyo/face-parsing)。

## 4. 数据处理设计

### 4.1 图纸裁切与逐格解码

1. 先做布局识别与图案面板确认，将标题、配色表和署名排除在推理输入外；保留完整原图和裁切变换。不写死“所有图片右侧某个矩形就是图案”。
2. 识别网格类型、行列数、格距、相位和占用；结合格线／珠粒周期、已有尺寸元数据及抽样校正。方格图先行，六角底板、多部件拼装和无法确认的布局单独排队，不强行拉成方格。
3. 从珠粒实色区域采样，避开中心孔、圆环边缘和网格线；不能简单取珠粒中心像素。白珠与空白底板分别判定，角色的白头发和眼白不能因此丢失。
4. 生成逐格占用、颜色索引和置信度，以及不含豆孔／图例的平面渲染视图。必要时用最近邻放大供识别，保留原图面板对照；不使用生成式超分补造五官。
5. 保存 `sheet → panel → grid → face → component` 的完整正反坐标变换，禁止用放大后像素尺寸充当模板格数。

这里的版面解析和格点测量负责读回已画出的图纸，不负责用几何规则猜眼、鼻、嘴；自动语义识别仍复用现成神经模型，延续原有约束。

### 4.2 分图与预标注

对比三种输入：完整图纸、仅图案面板、逐格还原的平面图。前者只作基线，后两者通过试验选择；不能预先认定去孔后的图一定更好。

完整脸采用“头／角色 → 脸部局部 → 眼、鼻、嘴”的层次识别，并记录每步未检出的原因。纯眼部图走已确认面板的部件识别入口，不以整个人物检测成功为前提；这是计划新增的离线适配，当前服务不保证可直接完成。

保留原始检测分、SAM 预测 IoU、蒙版及提示词，分别校准阈值。它们不是五官类别正确率，也不是可训练标签质量；Grounding DINO 的检测分和文本阈值本就属于不同筛选环节。[官方 Transformers 文档](https://huggingface.co/docs/transformers/model_doc/grounding-dino)。

输出分为两层：**部件支持区域**描述眼／嘴所在范围；**逐格颜色角色**描述其中的暗部、眼白、虹膜、高光等。二值眼睛蒙版不能直接当成全黑眼睛模板，也不能由黑色自动推断其属于眼睛而不是头发。

同一眼的多个珠粒、睫毛和高光需要按部件证据审核归属；不能沿用“一个连通域就是一只眼”的假设。位置与姿态按证据保留，左右以图像坐标命名并记录约定；只露一眼、闭眼、遮挡、无鼻／无嘴均允许，不镜像补齐。

### 4.3 审核与训练记录

每个实例建议记录以下字段，实际 schema 在实施阶段冻结：

| 字段组 | 必须保留的信息 |
| --- | --- |
| 来源 | `sheetId`、作者、URL、原图 SHA-256、使用范围、审核人／方式和版本 |
| 分组 | `designGroupId`、已知角色／身份、近似版本组、原始图纸组 |
| 几何 | 面板、脸和部件框；网格类型／尺寸；格坐标、局部锚点、变换链 |
| 语义 | `eye/nose/mouth`、图像左右、表情、朝向、可见／遮挡／不存在／未知 |
| 真值 | 逐格占用、颜色角色、保留底色、未知格、配套上下文、审定矩阵 |
| 模型证据 | 检测器与 SAM 权重、输入视图、提示词、阈值、原始分数、原蒙版 |
| 质量 | 自动候选／已校正／拒绝，修改耗时、失败原因、训练可用状态 |

不把低置信度漏检记成“该部件不存在”，未知格不参与监督。先用审定的实例训练；未经审核的伪标签仅单独留存，后期若研究半监督也必须与真值区分权重和评测。

## 5. 三层学习目标

### 5.1 模板库：先回答“有没有更好的候选”

从通过审核的格矩阵中提取眼、鼻、嘴，保留少量脸部上下文；聚类和去重获得代表设计，登记适用格数、姿态、表情、可用颜色角色及来源。现有 35 个规则模板仍作基线，小尺寸表达与无模板候选也保留。

按部件的实际宽高和可用格数分桶，而不是只看整张画布是 32 还是 96 格。初期重点覆盖 1–8 格宽高的可表达部件，超出范围单列；大图裁出的大眼睛不能简单缩到 3×3 后宣称保真。镜像、缩放和调色只用于受约束增强，不增加独立样本数；高光方向及不对称表达必须跟随变换审核。

### 5.2 模板选择模型：回答“当前输入适合用哪个”

输入：部件种类、局部图像／蒙版、表情与朝向证据、目标部件宽高、可用颜色／占格预算、检测可信度、相邻五官距离和候选模板特征。冻结的 DINOv2 局部特征可以作为对照，但对 1–3 格结构未必优于几何与颜色角色特征，不默认追加大编码器。

输出：合法候选的分数、拒绝／不使用模板的选择。先比较现有规则、最近邻与小型线性或 MLP 排序器；用真实接受／拒绝或 A/B/Tie 标签训练，避免自举现有启发式分数作为唯一真值。双眼仍通过现有联合搜索处理，不要求相同模板或等高等大。

监督分两种，分别记账：

- 图纸部件及其上下文可训练“从手工拼豆设计中找相似模板”，并评估库覆盖率。
- 照片／插画转换需要另补真实输入、固定分析证据、目标网格及人工接受的模板／局部修正。现有图纸通常没有其配对输入，不能据图纸重建分数宣称照片转换质量提高。

首轮沿用原 P9 建议的至少 180 个独立来源组、1,000 条有效部件接受／偏好记录作为标注预算起点。优先完成动漫插画域；人物照片和猫狗单独列域、单独评估，不能让动漫结果自动代表它们。

### 5.3 条件式模板生成模型：回答“能否产生更合适的新矩阵”

在库覆盖率和排序器通过门禁后，首轮采用小型条件 CNN 解码器，与简单基线比较；如出现明确的结构表达瓶颈，再考虑 Transformer 对照，不同时铺开多条大模型训练。

- 条件：部件种类、目标宽高与占格预算、表情／朝向证据、局部上下文特征、召回的模板原型。首个试验可生成对召回矩阵的有界修改，再比较从空矩阵生成。
- 输出：有限个（首轮至多 4 个）角色矩阵、占用／保留底色和锚点，或 `no_template`。尺寸候选由合法格数预算限定，角色集合按部件限制；不生成材料品牌 RGB 或整张脸。
- 训练：审定矩阵作监督，使用角色分类与占用损失，未知格屏蔽；几何／锚点和预算作为辅助约束。损失权重在开发集冻结，验证合法性时仍使用硬校验，不以低损失替代检查。
- 独立审定模板可先用于学形状分布和受扰矩阵的修复；这类自重建监督只能证明先验／解码能力。面向实际输入的条件生成仍需上述真实输入到审定局部目标的配对数据。
- 生成候选须通过边界、角色、预算、保护格、眼鼻嘴间隔和姿态检查，再参与候选排序；低置信、无法表达或超时回退到审定模板／原有投影／用户选择，不凭空补出不可见五官。

建议的试验预算是至少 300 个独立设计来源组、2,000 个审定部件实例，并覆盖主要尺寸与表情；这些是工程起点，**不是文献保证的最低样本数或达标证明**。以有效分组数量、学习曲线和留出测试置信区间决定是否值得继续；目前不能声称已拥有这些训练样本。

首个生成模型用于离线生成候选、审核并冻结为版本化模板库，便于复用现有前端与放置器。只有证明按当前输入在线生成有额外收益，才规划独立推理接口；离线先验生成与在线条件生成的能力分开验收。即使生成器没有胜出，已验证的模板库和选择模型仍可形成第一阶段成果。

| FT5.1 冻结模板契约 | 扩展来源、训练版本及角色／保留底色表达；校验 ID、尺寸、锚点、角色和哈希，拒绝版本不兼容的产物 | 模板契约、兼容清单、版本化注册包 |
| FT5.2 接入候选流程 | 复用颜色解析、放置、双眼联合搜索和质量门禁，保留不使用模板候选；先通过显式实验开关验证 | 集成候选与诊断；模板／模型／色卡版本可追溯 |
| FT5.3 验证完整结果 | 在最终配色与精修后重新检查五官可见性、碰撞、姿态、材料统计和导出一致性；人工覆盖与锁定优先 | 三套色卡端到端报告、失败回放、受影响接口测试结果 |
| FT5.4 演练回退 | 模拟缺模型、超时、非法输出、所有候选被拒、版本不匹配等故障；回到审定库／原规则并说明原因 | `release/rollback-report.md`，回退前后与原基线对照 |

**推进条件**：功能和效果均有真实验收证据，原有规则回退可用，手动修改不被覆盖，最终图纸满足冻结预算。在线生成若另行采用，需增加接口、延迟、并发、超时和资源预算验证；离线模板包验收不代表在线推理已完成。

**不满足时**：保持实验开关和旧默认行为，按错误类别回到相应阶段修正；失败清单留存，不放宽质量门槛来完成集成。

当前状态统一维护在开头的 FT 阶段表。各阶段都需要明确的推进报告；进入下一阶段不表示上一阶段所有题材自动达标，未覆盖组继续保留限制。

## 7. 切分、指标与通过条件

### 7.1 防止“同一张脸换色后进入测试集”

按原图纸、设计近似组及已知身份／角色关联分组，固定 train/validation/test（优先沿用 60/20/20）；同图的裁剪、左右眼、不同尺寸、镜像、不同色卡与增强版本都进入同一组。角色未知的组标记未知，保守合并明显近似图；再用按作者留出的补充测试观察风格泛化，不把作者当成唯一去重依据。

先切分再聚类、挖模板、学习特征统计与训练。**用于测试的手工部件不能提前进入检索模板库**，否则“能找到正确模板”可能只是记住测试样本。现有独立编写的规则模板作为固定公共基线；封存集只用于最终判断，阈值不按测试结果回调。

### 7.2 指标分层

以下数值是拟议的首轮工程门槛，实施前在 FT0 冻结；小样本的不确定性须报告，后续变更须说明原因并使用新的封存集，不能追着测试分数放宽。

| 层次 | 评测内容与拟议门槛 |
| --- | --- |
| 版面／网格 | 报面板成功率、支持布局覆盖率、行列数／相位错误、白珠和空白混淆；自动接受的方格样本，审核格级占用／颜色索引一致率目标 ≥99%，同时逐图报告，避免大图均值掩盖小图错误 |
| 部件预标注 | 对可见、可表达部件分别报 Precision／Recall；自动接受候选精确率目标 ≥95%、召回目标 ≥80%；同时报自动接受覆盖率和每图修正成本，不能靠只接受少量易例达标 |
| 整理成本 | 在相同难度组比较纯人工与预标注＋校正；拟以人工校正耗时中位数降低 ≥30% 作为扩大批量的成本目标，同时报告总耗时、样本量与不确定性；未达到时选择人工小库或半自动路线 |
| 定位／蒙版 | 报格坐标中心误差、支持格集合 F1、漏／多部件数；小于三格的部件单独报错格数，不只报像素 IoU；多主体串脸、珠粒误拆均单列 |
| 模板产物 | 所有导出模板通过 schema、边界、角色和占格校验；零未解决的硬碰撞／越界／锁定格改写；审核后矩阵与预览可互相重建 |
| 最终五官 | 沿用现有 gate：眼 Top-2 接受率 ≥90%、嘴 ≥85%、可表达硬特征完整可见率 ≥95%、硬碰撞 0；同时报告鼻、Top-1、错表情、无依据新增及全部失败比例 |
| 整体提升 | 固定参数盲评，报告胜／平／负、净胜差及按来源组自助采样的 95% 置信区间；主目标组的改善区间须排除 0；证据不足继续实验，不宣称优于基线 |
| 回归与成本 | 24／123／291 分别检查色数预算、局部色差、轮廓侵占和精修后可见性；沿用冻结的配色容差，报告耗时、峰值显存、模型大小、回退率 |

“不可见”“无法在当前格数表达”“未检出”分开计数；条件接受率同时给出全部输入的总体成功率及分母。最低保留原 gate 的 30 个独立人物输入与 32／48／64 格回归，并为本轮增加动漫主目标、96 格、矩形画布、侧脸、闭眼、眼镜、遮挡和动物分组；样本不足的组标为证据不足。

### 7.3 消融与错误归因

固定同一输入、色卡、画布、色数预算、分析证据与精修配置，比较：

1. 源图局部直接投影／不用模板。
2. 现有 35 模板与现有规则。
3. 提取模板库＋固定规则。
4. 同一模板库＋学习选择器。
5. 生成候选＋相同选择与放置策略。

另分别在审核证据和真实自动证据下评估：前者估计模板链路上限，后者衡量产品效果。若审核证据下提升明显、自动证据下失败，优先改定位／审核入口；若候选有人接受却没选中，改排序；若正确选中但精修抹掉五官，修保护链路；若所有候选都差，再扩模板或研究生成器。

## 8. 风险预案与停止条件

每个问题先保留输入、版本和失败证据，再处理其发生的阶段。不能用更大的模型掩盖读格错误，也不能用调整最终色差指标掩盖模板错位。

| 风险／触发信号 | 优先检查和处理 | 可继续的范围与必须保存的产出 |
| --- | --- | --- |
| 图例、标题或署名被当成五官 | 检查面板确认与反投影，修裁切／布局；通过人工面板对照判断是否为检测误报 | 仅确认后的面板继续，保存错误框及布局修订，不把整页高分当成成功 |
| 格距／相位偏移导致裁剪错一格 | 对格点叠图核查行列、边界和相位；已知尺寸仅作交叉校验，不能压制真实不一致 | 停止该图的模板导出；修读格后失效其下游缓存并重建 |
| 白珠被当空白，或豆孔被当眼睛 | 比较占用、颜色采样位置与平面还原；使用珠粒实色区域和布局证据，保留白色区域人工核对 | 对读格不确定的样本标未知；不以大面积填色掩盖损失 |
| 原图尺寸不足、格数过密、圆环无法分辨 | 检查原始下载是否为完整图纸，估计每格像素支持；放大只能帮助查看，不能增加真值 | 缺乏可读信息的图不进入逐格监督，保存不可恢复原因；不使用生成式超分造标签 |
| 角色／头部漏检，整条部件链无输出 | 用已确认面板／脸框进行局部对照；分开判断检头失败和检五官失败，必要时比较现成动漫定位器 | 可转人工框／点辅助分割；完整脸和独立眼部走不同入口，记录路线来源 |
| 一眼被拆成多眼、眼睛与头发黏连 | 检查格图还原、支持区域与部件归属；按语义候选和脸部上下文审核，不能用连通域数决定眼数 | 暂停自动接受该类型，校正后继续；保存原始蒙版与合并／拆分依据 |
| 遮挡、闭眼或原设计没有鼻嘴被强行补全 | 核查可见性标签与无模板候选；模型未检出不等于不存在，左右互相复制不是证据 | 保留无该部件或未知状态；无依据新增列为硬失败，检查召回与生成两个环节 |
| 眼白／高光／虹膜角色混淆 | 对照原格颜色、相邻结构和审核样例；定义不一致时先修标注协议，未知角色不参与损失 | 可缩为确定角色的任务；禁止为了数量把不确定标签当金标准 |
| 不同审核者分歧大、同标签含义不同 | 对争议样例双人复核或由指定审核者裁定；随机抽查已接受项，记录一致性与修改版本 | 先冻结标注说明再扩批；未解决争议从训练监督中屏蔽，保持测试分母可见 |
| 来源资格未确认，合格训练量为零或不足 | 审查资格字段和用途范围，补自绘／明确可用数据；裁剪和伪标注不改变来源状态 | 可以保留流程与参考目录，训练阶段明确未具备条件，不产出声称合格的权重 |
| 近似图、同角色或同设计跨集合 | 检查原图／设计／身份组和近邻矩阵，先切分再挖模板；发现交叉立即标记相关结果失效 | 重新分组并训练评估，保留泄漏报告；不能只从最终报告删除困难项 |
| 独立数据不足或类别极不平衡 | 报来源组与部件数量，区分不同尺寸／表情；优先补稀缺桶，不用镜像换色充数 | 缩小模型适用范围，稀疏桶回退规则；学习曲线与覆盖缺口进入报告 |
| 图纸自重建很好，真实输入转换没有改善 | 核查训练任务与输入域，补配对转换／接受标签；分别衡量先验和真实条件生成 | 保留模板库研究成果，不宣称产品提升；回到 FT3 监督建设 |
| 大模板好看，放进目标脸部后拥挤变形 | 以部件格数和邻域间隔复查，不以整体画布尺寸决定模板；比较更小模板及无模板候选 | 原始姿态与硬间隔优先，无法表达则建议增大画布或回退；不移动锁定位置换分数 |
| 五官选对但最终被改色、抹除或碰撞 | 导出放置、量化和精修后的同一部件；分别定位角色绑定、颜色预算和保护链路 | 回修相应阶段，不重新训练生成器掩盖后处理缺陷；保存分阶段图纸 |
| 新模型劣于规则，或只在单一色卡提升 | 检查独立组统计、硬约束及分卡结果；选择器／生成器分别消融 | 不默认启用；可限定已经验证的适用域／色卡，但需明确限制和回退，三卡整体训练不标完成 |
| 显存不足、吞吐过慢或任务中断 | 从单 GPU 串行、小批次和常驻模型开始，测量后调资源；按阶段缓存恢复，限制重试 | 暂停扩批，保留资源日志与未完成清单；不能跳过样本后仍报全量完成 |
| 标签、模型或解码版本变更后结果不一致 | 核对内容／配置／版本哈希，依赖变化使下游缓存失效；人工改动留独立修订 | 重建受影响产物并重新验收，发布包保持固定版本，不覆盖历史证据 |

### 停止或切换路线的明确规则

- **先停数据进入训练**：格矩阵不可恢复、使用范围未确认、角色标签冲突未解决或发现切分泄漏。已经完成的目录和中间产物保留，但不升级为训练真值。
- **切到半自动**：读格可靠，模型候选召回或部件归属不稳定，而人工框／点校正具有可测成本优势。报告中明确人工参与和自动覆盖率。
- **保留规则／检索**：新增模型未通过独立组提升与回归门槛，或对小尺寸／稀疏组更差。生成模型不是强制发布项。
- **暂停扩批**：人工审核积压、推理错误率、磁盘或显存超出 FT0 冻结预算；先处理原因，再从可追溯断点恢复。
- **允许完成一次失败试验**：结论可以是“当前数据和路线不值得继续”，但必须交付证据、失败分类和下一步选择；不能将负结果改写为成功，也不无限追加训练轮次。

## 9. 首轮边界与预期交付

首版重点是动漫方格图的眼、鼻、嘴；动物和真人作为扩展域及回归组，不承诺一次混训覆盖全部对象。首轮不微调 SAM2／GroundingDINO，不重写语义定位模型，不把 Perler 配色任务与形状学习混成一个问题，也不直接训练整张脸的自由生成网络。

实施后的交付应包含：模型身份核对、试验分图报告、可追溯的部件与逐格数据、冻结切分、版本化模板图鉴、选择模型、生成模型的独立对照结论、三套色卡最终效果与失败图集，以及回退方案。仅有裁剪 PNG、分割成功日志或训练 loss 下降不构成交付完成。

当前最值得启动的下一步是 **FT0＋FT1：冻结版本与评测协议，验证约 240 张规模的图纸解码与候选五官提取是否能明显减少人工整理成本**。本轮仅完成本计划及计划入口更新。
