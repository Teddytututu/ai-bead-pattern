# 明暗与保色首批实现记录

实施开始：2026-09-26；最后验证：2026-09-27。算法版本：`0.8.0-color-fidelity`。

本次完成 P1 首批代码与本地回归，历史验收状态保持不变。完整的多场景真实质量 gate 尚未完成，不能据此宣布 P1 整阶段或后续 P2–P10 已交付。

## 已实现

- MVP 明暗收敛为一个 Lab 阶段，移除该路线的 RGB 风格调整与 RGB 明暗分档叠加。A0/A1 保留历史采样基线行为，不适用新的明暗策略。
- `structure.valueMode` 支持 `preserve / adaptive / stylized`；默认还原风格 preserve、简洁 adaptive，其余 stylized。`valueStrength` 范围 0–1，零强度真实旁路；preserve 的生效强度固定为 0。
- 每格保留原来的 a*/b*，不再用区域平均色度覆盖。非描边格的 L* 与 ΔE00 预算分别为 adaptive ≤6、stylized ≤12，再乘以强度。预算施加于量化前；不保证最终实体色号同样满足该上限。
- 平坦区域允许重合的明暗角色，不硬造 6/8 个单位的层级差。语义间距只作用于相邻来源区域，受偏移预算约束；不满足的间距如实报告，避免将浅色眼区无限压黑。
- 轮廓在明暗角色之后单独插入，只修改选中的线条格；其亮度/ΔE00 预算为 20。轮廓开关不再提亮内部。完整外/内轮廓规则仍归 P2，本次没有提前宣告一格线条验收完成。
- 配色按逐格颜色证据选色和分配，避免同一明暗角色全部变成一种材料色。选色搜索将成本按最近材料色聚合，最终逐格匹配仍使用原有 Lab；这是选色近似，不宣称有限色数下的全局最优解。
- 原图保真参与颜色评分：还原风格 `85% sourceFidelity + 15% planFidelity`，其余 `55% + 45%`。旧排序权重不等于已经重新训练的模型。
- 新增核心 `valueDiagnostics` 和 `colorDiagnostics`：相对同一采样原图，分别统计结构映射、明暗、量化、最终结果的均值/中位数/P95 ΔE00、亮度与色度偏移，并记录受限格数和实际颜色规划路线。各阶段色差不可相加。
- Demo、小程序控件、API 校验、OpenAPI、微信 SDK 请求类型与透传均支持新参数；导出元数据保存实际模式/强度/算法版本。

`preserve` 保证明暗阶段保持局部 Lab；采样、几何映射、有限色卡、五官增强、去噪与精修仍可能改变最终颜色。这些影响在阶段诊断中分开记录，后续 P4 再完成身份花纹的全流程保护。

## 确定性回归

| 旧问题 | 新行为 |
|---|---|
| 同一区域 `[50,50,30]` 与 `[50,-20,-30]` 都变成 `[50,15,0]` | 明暗阶段保留各自 a*/b*；有对应色号和预算时逐格配色保留不同颜色 |
| 眼区 L*=70 因肤区 L*=35 被降至 31 | 保色保持 70；适度增强最多下降 6，不能为满足语义间距越过预算 |
| 5×5 平坦图开启轮廓后内部 L*=50 变成 56 | preserve/adaptive/stylized 下开关轮廓均保持内部一致 |
| 强度 0 仍继续调整 | 有/无语义两条生成路线均验证零强度旁路，并检查 API、SDK、导出元数据 |

另补齐 34 组 CIEDE2000 参考颜色对及反向对称验证，允许误差 `<0.0001`；使用作者公开数值验证项目自己的实现，没有复制其 MATLAB 程序。[Sharma/Wu/Dalal 数据说明](https://hajim.rochester.edu/ece/sites/gsharma/ciede2000/)、[参考数据](https://hajim.rochester.edu/ece/sites/gsharma/ciede2000/dataNprograms/ciede2000testdata.txt)。

## 运行

```powershell
pnpm demo
# 已有最新构建时快速启动
node scripts/serve-demo.mjs
# 重现当前样图对照，先确保 pnpm build 已执行
node scripts/benchmark-value-fidelity.mjs --label current
# 对自己的本地图片试跑，不自动纳入训练
node scripts/benchmark-value-fidelity.mjs --input test.jfif --label local
```

Demo 选择“结构版 → 颜色策略 → 保色”，关闭描边可单独查看明暗修正；随后试适度增强/风格化以及强度 0。小程序重新运行 `pnpm wechat:build` 后使用对应控件。API 示例见 [接口说明](../services/pattern-api/README.md)。

全项目自动测试先完成 711 项；随后补充标准色差与零强度端到端用例，核心 405 项、API 7 项通过，其余已通过测试未重复无关运行，当前覆盖合计 713 项。构建、全项目类型检查与小程序 TypeScript 检查通过。浏览器首轮 15/18 通过，三个超时项在修正后复测 3/3 通过（34.2 / 33.3 / 30.1 秒）；18 条流程均已覆盖通过。截图为 `output/value-policy-demo.png`。微信开发者工具交互及真机本次未运行，不计入浏览器验收结果。
